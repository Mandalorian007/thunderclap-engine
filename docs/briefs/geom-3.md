## Goal

The geometry operations a 3D action game needs past builders and welds: mesh simplification for LODs with a chain the renderer can pick from by screen size, a convex hull and a decimated collision proxy so a collider is not the render mesh, splitting and slicing, and the small debts (clone, positions-only collider source, tangent-aware merge/transform). Plus the 2D tile slide the platformer template still hand-rolls. All CPU, allocation-light, no new ties outside `geom` (and `render` for the LOD pick, types only).

STATUS row, *done when*:

- **Debts**: `cloneGeometry(g)` (deep copy, every lane); `GeometrySource` accepts `{ positions: Float32Array, indices, transform?, layer? }` (positions-only, 3 floats per vertex) beside `{ geometry }` (the BVH build reads positions through one accessor either way; `bake.mjs` needs no change, say so after reading it); `mergeGeometry` and `transformGeometry` handle `VERTEX_LAYOUT_3D_TANGENT` (and any layout with a `tangent` lane: transform rotates the tangent xyz, keeps w) with a test per op; render README *Vertex layouts* table lists every attribute location (0..2 vertex, 3..9 instance, 11/12 skinning, 13 tangent, uv1 if render-4 added one: coordinate by reading main at your gate, additive row only). Verify the in-place callout for `transformGeometry` in the geom README and close the collide wish.
- **Simplify** (`src/geom/simplify.ts`): `simplifyGeometry(g, { targetRatio | targetTriangles, preserveBorders?: boolean, preserveUvSeams?: boolean, errorLimit? })` → `{ geometry, error }` quadric-error edge collapse (Garland–Heckbert) over the welded position set, carrying uv/normal/colour lanes by the kept vertex, re-welding at the end; deterministic (sorted candidate heap with index tie-break). `createLodChain(g, ratios: number[])` → `Geometry[]` (level 0 is `g`). Tests: a 10k-triangle sphere at 0.25 has ≤ 25% + 2 triangles and every kept vertex lies within `errorLimit` of the original surface (sampled); `preserveBorders` keeps a plane's rim vertices; two runs are byte-identical.
- **LOD pick** (`src/geom/lod.ts`): `selectLod(chain: readonly { radius: number }[] | number, boundsRadius, distance, fovY, viewportHeight, thresholdsPx: number[])` → level index from projected size in pixels (pure function, no renderer); `LodChain` type `{ geometries, meshes?, thresholdsPx }` is storage only. The renderer is not changed: a game (or ws/render-5) calls `selectLod` and draws that mesh; the geom README shows the three-line loop. Test: the level steps at the exact pixel thresholds and clamps at both ends.
- **Hull and proxy** (`src/geom/hull.ts`): `convexHull(positions | Geometry)` → `Geometry` (3D quickhull, outward winding, flat-shaded normals); `collisionProxy(g, { maxTriangles, kind: 'hull' | 'simplified' })` → a `Geometry` meant for `GeometrySource` (hull or a simplify with `preserveBorders` and no uv lanes). Tests: the hull of a cube's 8 corners plus interior noise is 12 triangles; every original vertex is inside or on the hull; the proxy of a 20k-triangle rock is ≤ `maxTriangles` and `raycast` through its BVH hits within 2% of the full mesh on 100 random rays.
- **Split and slice** (`src/geom/split.ts`): `splitGeometry(g, by: 'island' | ((triIndex) => number))` → `Geometry[]` (connected components over shared welded positions, or a caller key); `sliceGeometry(g, plane: { nx, ny, nz, d }, { cap?: boolean })` → `{ above, below }` with the cut edges triangulated into cap faces when `cap` (uses `src/geom/triangulate.ts`). Tests: two separate cubes merged then split give two; a sliced cube has two closed halves with the cap area equal to the cross-section; slicing a plane through no triangles returns the original on one side and an empty geometry on the other.
- **2D tile slide** (`src/geom/collide/tile-slide.ts`, only if nothing on main does it): `slideTiles(grid: GridSource | { solidAt(cx, cy) => TileKind }, box: { x, y, w, h }, dx, dy, out: TileSlideResult, { oneWay?: boolean, stepUp? })` axis-separated AABB vs tiles with one-way platforms (solid from above only when moving down and the box's bottom was above the tile top), `TileSlideResult` `{ x, y, dx, dy, onGround, hitCeiling, hitWall, carried?: { dx, dy } }`; `carryBy(result, mover: { dx, dy })` applies a mover's delta before the slide for carried-platform semantics. Tests: a one-way platform passes from below and holds from above; a mover carries the box; corners do not snag at tile seams. If `slide2` already does this, document the recipe in the README instead and say so.
- **Harness**: `harness/geom3.html` + `geom3.ts` + `geom3-state.ts`: `?lod` (a rock at four distances, state `levels: number[]`, `triangles`), `?hull` (a torus and its hull, state `hullTriangles`), `?slice` (a cube sliced by a plane that sweeps over time, state `capTriangles`, `closed`), `?tiles` (a box on one-way platforms and a mover, state `onGround`, `carried`) or omitted if the slide is documented only, `?still` parks. `e2e/geom3.spec.ts` (E-017 polling), existing geom/collide specs green, `pnpm snap:check` 0 px.
- **Docs**: geom README sections *Clone*, *Simplify and LODs*, *Hull and collision proxy*, *Split and slice*, *Tile slide* (or the recipe), the collider source paragraph for positions-only, types list; render README table row(s); CHANGELOG block; ARCHITECTURE geom clause (one sentence); root README harness list + count line.
