## Goal

The pieces a game needs between the HUD and the world: a tooltip that follows a world point or a DOM element with a delay and an arrow, a pad or keyboard driven world cursor that steps over a grid or snaps between targets and fires select, a loading screen with a progress bar and a tip line, a notification stack distinct from toasts, and the three small fixes above. All on the public overlay, all keyboard and screen-reader clean, no new overlay layers.

STATUS row, *done when*:

- **`h` string styles**: `h(tag, { style: 'color: red' })` sets `cssText`; an object keeps today's behaviour. Test.
- **Tooltip** (`src/ui/tooltip.ts`): `ui.tooltip(target, content, { delay: 400, placement: 'top' | 'bottom' | 'left' | 'right' | 'auto', arrow: true, interactive: false })` where `target` is an element (hover + focus show it, pointer leave + blur + Escape hide it) or an `AnchorHandle`/world point `[x, y, z]` (it rides `Anchors`, hides with it); one shared tooltip element per overlay (`role="tooltip"`, `aria-describedby` wired on element targets), flips placement when it would leave the viewport, `set(content)`, `show()`, `hide()`, `dispose()`. Tests: show after delay, hide on leave, flip at an edge, world target follows the anchor.
- **World cursor** (`src/ui/cursor.ts`): `ui.cursor({ mode: 'grid' | 'targets', step: (dx, dy) => void, targets: () => WorldTarget[], onSelect, onMove, repeat: { delay, interval } })`: in `grid` mode d-pad/arrow keys step by `(dx, dy)` with latching and repeat (reuse `padnav`'s latch), A/Enter selects; in `targets` mode the cursor snaps to the nearest target in the pressed direction (angle-weighted, like a console menu), with `cursor.position` and `cursor.target`; a cursor element on the `hud` layer anchored through `Anchors` so it draws over the world point; `enable()/disable()`, respects `menu-nav` focus (a modal panel takes the pad; the cursor resumes after). Tests on the direction picking and the latch; a DOM test for the anchor.
- **Loading screen** (`src/ui/loading.ts`): `ui.loading({ title, tip, progress })` on the `panels` layer: a `bar` widget, a `tip` line that can rotate through strings, `set(progress, label?)`, `done()` fades it out and resolves after the transition, `aria-busy` on the overlay root while shown, pad and keys swallowed while visible. Test: progress text, `done` resolves, root `aria-busy` toggles.
- **Notifications** (`src/ui/notify.ts`): `ui.notify({ title, body, icon, tone, actions: [{ label, onClick }], timeout })` stacked top-right distinct from `toasts` (bottom-centre, text only); `role="status"` with `aria-live="polite"`, pad navigable actions through `menu-nav` when focused, `dismissAll()`. Tests.
- **Select zoom fix**: `styles.ts` select/range rule stops double-scaling native selects on frame layers (the backlog line names the cause: token already scaled, then zoomed again). The ui snapshot pages must stay pixel-identical: if a golden shows a select, say so and keep the fix behind the layer condition that only the HUD layer takes.
- **Harness** `harness/ui.html` gains `?tooltip` (three buttons and one world point with tooltips), `?cursor` (an 8×8 grid of targets, grid and targets modes toggled by `?mode=`), `?loading` (a bar driven by a timer, `?stall` holds it at 0.4), `?notify`; state exposes `tooltipVisible`, `tooltipPlacement`, `cursorCell`, `cursorTarget`, `loadingProgress`, `notifications`. `e2e/ui.spec.ts` adds: tooltip appears after hover delay and hides on leave on pointer rows (touch rows skip); keyboard focus shows it on every row; cursor steps by arrows and by polled fake-pad presses (same latch as menuNav; polled, not fixed waits); targets mode picks the right neighbour; loading `done` removes the panel and clears `aria-busy`; notify action fires by Enter; existing ui tests green; `pnpm snap:check` 0 px.
