## Goal

Collision queries a 2D or 3D game calls every frame against static geometry: build a static collider from one or more `Geometry` (triangle soup with a bounding-volume hierarchy), heightfields and 2D tile grids; overlap, raycast and *sweep* shapes (sphere, capsule, AABB, 2D circle/box) against it; and a `slide` helper that applies the usual move-and-slide (iterate the sweep, project the velocity on the hit plane, up to N iterations, with step-up and slope limits) so a character controller is ten lines in the game. Pure CPU, no GPU, no allocation per query after warm-up, every result written into an `out` the caller owns.

STATUS row, *done when*:

- **Static world** `createStaticCollider(sources: ColliderSource[], opts?: { leafSize?: number }) → StaticCollider` where `ColliderSource` is `{ geometry: Geometry, transform?: Mat4 | Float32Array, layer?: number, userData? }` or `{ heightfield: Heightfield, layer?, userData? }` or `{ grid: { width, height, cellSize, origin: [x, z], solid: (x, z) => boolean | Uint8Array }, layer?, userData? }` (the 2D tile case, treated as unit boxes in xz); builds a BVH (SAH or median split, `leafSize` 4 default) over triangles in `Float32Array`s; `collider.bounds`, `collider.triangleCount`, `refit(sourceIndex, transform)` for a moving platform (refits the sub-tree, no rebuild), `remove(sourceIndex)`; `exportCollider(c) → ArrayBuffer`/`importCollider(buf)` (bake at build time, ship bytes; the engine never fetches).
- **Shapes** `Sphere { x, y, z, r }`, `Capsule { x, y, z, halfHeight, r }` (y-axis), `Aabb { min, max }`, `Circle { x, z, r }`, `Box2 { x, z, hw, hh }` as plain-object types; `shapes.ts` has `closestPointTriangle`, `sphereTriangle`, `capsuleTriangle`, `aabbTriangle`, each pure and tested.
- **Queries** (all with `layerMask?`): `raycast(c, origin, dir, maxDist, out: Hit) → boolean` (`Hit { t, x, y, z, nx, ny, nz, triangle, source, userData }`), `overlap(c, shape, out: Contact[] (preallocated by the caller; returns the count written), maxContacts)` (`Contact { depth, nx, ny, nz, px, py, pz, triangle, source }`), `sweep(c, shape, dx, dy, dz, out: SweepHit) → boolean` (time of impact 0..1 along the displacement, normal, point; conservative-advancement or swept-sphere/capsule vs triangle analytically, say which), 2D variants `raycast2`, `overlap2`, `sweep2` in xz for `Circle`/`Box2` (the grid source makes these fast for a tile game).
- **Move and slide** `slide(c, shape, dx, dy, dz, opts: SlideOptions { maxIterations 4, skin 0.005, maxSlope (deg, 50), stepHeight 0.35, snapDown 0.2, layerMask? }, out: SlideResult { x, y, z (final position), grounded, groundNormal, hitWall, hits: number, remaining: [dx, dy, dz] }) → SlideResult`: sweep, move to the hit minus skin, project the remaining displacement on the hit plane, repeat; a hit whose normal is steeper than `maxSlope` counts as a wall; when a wall blocks horizontal movement and the shape fits `stepHeight` higher, step up; after the move, snap down `snapDown` when `grounded` was true and the ground is within reach so stairs do not launch the capsule; `slide2` for the 2D case (circle or box in xz, no step/slope).
- **Debug** `colliderWireframe(c, out?: Float32Array) → Float32Array` of line segments (the BVH leaves or the triangles, flag) for `createDebugDraw`.
- **Tests:** BVH equals brute force on 200 random rays and 50 random sphere overlaps against a `box`+`stairs`+`heightfield` world; capsule sweep against a floor stops at the floor with `t` within 1e-4 of analytic; slide along a 45° wall keeps speed × cos; slide up `stairs({ rise: 0.2 })` climbs every step and ends `grounded`; slide against a 60° slope with `maxSlope 50` treats it as a wall; snap-down keeps `grounded` across a 0.15 drop; `refit` moves a hit; export/import round-trips byte-equal and query-identical; allocation test: `slide` 1000 times after warm-up allocates nothing (array identity or a counting stub as nav does); the 2D grid: a circle slides along tile walls through a corridor one tile wide without snagging on corners (the dungeon `moveBox` case).
- **Bench:** a timing test (log, not assert): 100k triangles, 10k sweeps, in Node.
- **Harness** `harness/collide.html` + `collide.ts` + `collide-state.ts`: a level from `geom` (`box` floor, `stairs`, `arch`, a ramp, a heightfield patch) merged into one collider; a capsule driven by WASD/stick with `slide`; the BVH or triangle wireframe through `createDebugDraw`; `?grid` switches to a 2D tile corridor with a circle; state exposes `pos`, `grounded`, `hits`, `triangleCount`, `lastSweepT`, `wireLines`. `e2e/collide.spec.ts` on the matrix: the capsule stops at a wall (x unchanged after 1 s of pushing), climbs the stairs (y increases by the known rise × steps), is `grounded` on the ramp, the 2D circle traverses the corridor; probes after a `?still` settle. `pnpm snap:check` unchanged.
- **Docs:** geom README gains *Collision* (collider, shapes, queries, slide, 2D, serialisation, with the ten-line controller example) or a new `src/geom/collide/README.md` linked from it; CHANGELOG one block; ARCHITECTURE *Geometry* one sentence; root README harness item. The *Not here* line in the geom README says what still belongs to the game (response forces, physics integration, triggers).
