## Goal

A glTF loads as a fully-lit PBR asset through the standard material: metallic-roughness, normal, occlusion and emissive maps and factors from the file, skinned primitives drawn through the standard material's skin binding without the game writing WGSL, mesh tangents used when the file has them, KHR_texture_transform and KHR_materials_emissive_strength honoured, texture sampler settings from the file, and the loader's own lit material retired behind an option. This is what makes the third-person template's character and cosmetics look like the quality bar.

STATUS row, *done when*:

- **Parser** (`src/assets/gltf.ts`): `GltfMaterial` gains `metallicFactor`, `roughnessFactor`, `metallicRoughnessTexture`, `normalTexture` + `normalScale`, `occlusionTexture` + `occlusionStrength`, `emissiveTexture`, `emissiveFactor` (× `KHR_materials_emissive_strength`), per-texture `texCoord` and `KHR_texture_transform` (offset, rotation, scale) carried as a `TextureRef { index, texCoord, transform? }` on every slot (base colour included; keep the old `baseColorTexture: number | null` and `texCoord` fields as deprecated getters for one release, or migrate the two call sites and say so); `GltfTexture` gains `sampler` (mag/min filter, wrap S/T mapped to engine `SamplerDesc`); primitives read `TANGENT` (vec4) and `TEXCOORD_1` when present; `warnings` lists any extension still ignored. Tests on a hand-built document covering every field, defaults when absent, and the transform math.
- **Loader** (`src/assets/gltf-load.ts`): each glTF material becomes a `createStandardMaterial` with every map bound (one engine `Texture` per (image, sRGB flag) pair: base colour and emissive are sRGB, the rest linear; `Texture` creation must take the colour space, read `src/render/texture.ts` and use what is there, if nothing, the wish goes to the report and you upload linear), the file's sampler, `alphaMode`/`alphaCutoff`/`doubleSided`, `KHR_texture_transform` applied through the standard material's uv transform if it has one, otherwise baked into a per-material uniform you add to `StandardMaterialDesc` as `uvTransform?: [sx, sy, ox, oy, rot]` (one new optional field, default identity, zero cost when absent); primitives with `TANGENT` build `VERTEX_LAYOUT_3D_TANGENT` meshes and the standard material uses the mesh tangent frame when the layout has one (a WGSL variant or an `@if`-style feature flag; read how `standard.ts` builds its shader); primitives without tangents but with a normal map keep the derivative path; skinned primitives (`JOINTS_0`) build `VERTEX_LAYOUT_SKINNED` meshes (flip the `SKINNED_LAYOUT` placeholder) and the loader creates the material with `skin: scene.palette` when `opts.palette` is given, else documents that the game sets `material.bindings.setBuffer(0, …)`; `opts.material` still overrides everything; `opts.lit: 'standard' | 'lit'` defaults to `'standard'`, `'lit'` keeps the old material for the 2D-ish toon look; `scene.materials[i].name` from the file.
- **Skin names**: `skeletonFromSkin(doc, i)` returns joint names from the node names (ws/skin wish) so `skeleton.joint('hand_r')` works; test.
- **Harness** `harness/gltf.html` gains `?pbr` loading a procedurally generated glTF (build the glTF JSON + buffers in the harness, no binary asset: a sphere grid with metallic × roughness, a normal-mapped tile, an emissive strip, a texture-transformed quad, a skinned two-bone cylinder animated through `skeletonFromSkin` + the standard skin binding); state exposes `materials`, `maps` (count of bound textures), `skinned` (true when the cylinder draws through `VERTEX_LAYOUT_SKINNED`), `tangentMeshes`, `warnings`. `e2e/gltf.spec.ts` adds: `?pbr` boots with `materials` = 5, `maps` ≥ 6, `skinned` true, `tangentMeshes` ≥ 1, `warnings` empty, no console errors, on every row; a pixel probe at the emissive strip is brighter than the surround (bloom path) and the metallic sphere differs from the matte one.
