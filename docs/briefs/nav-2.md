## Goal

Navigation for levels that are meshes, not grids: bake a navmesh from triangle geometry (walkable by slope and agent height/radius, rasterised to a grid, then regions and convex polygons), path over it with A* on the polygon graph and a funnel to a smooth path, support off-mesh links (ladders, jumps, doors), and steer a crowd with reciprocal avoidance so twenty agents heading for the same point do not stack. Same rules as `nav`: pure CPU, no engine imports (reading a `Geometry`-shaped `{ positions, indices }` object is fine; do not import `geom`), no allocation per query after warm-up, every call writes into an `out` you own.

STATUS row, *done when*: `bakeNavMesh(input: { positions: Float32Array, indices: Uint16Array | Uint32Array, stride? }[] | NavBakeSource, opts: NavBakeOptions { cellSize, cellHeight, agentHeight, agentRadius, agentMaxClimb, agentMaxSlope (deg), minRegionArea?, maxEdgeLength?, maxSimplification? }) → NavMesh` (voxelise triangles to a heightfield of spans, filter by slope/height/climb, erode by radius, flood regions, trace and simplify contours, triangulate to convex polygons, build the polygon adjacency); `NavMesh { polys, verts, adjacency, bounds, version, findNearestPoly(x, y, z, out), findRandomPoint(out, rng?), raycast(from, to, out) (walkable-surface ray, stops at the first boundary edge), height(x, z) at a point on a poly }`; `findMeshPath(mesh, from: NavPoint3, to: NavPoint3, out: NavPath3, opts?) : boolean` (A* over polygon centres or portal midpoints, then a simple stupid funnel into `out.points` as x, y, z triples; `NavPath3` mirrors `NavPath` with a `y`); `followPath3` (as `followPath`, height from the mesh); `addOffMeshLink(mesh, { from, to, radius, bidirectional, cost, userData? }) → id` and `removeOffMeshLink`, treated as edges by the search and surfaced in the path as `links: { index, id }[]` so the game plays the ladder/jump animation; `createCrowd(opts: { maxAgents, maxNeighbors?, timeHorizon?, neighborDist? }) → Crowd { add(agent: { x, z, radius, maxSpeed, prefVelocity }) → index, remove, setPrefVelocity, update(dt) (ORCA/RVO2-style reciprocal velocity obstacles, uses a uniform grid for neighbours, writes each agent's `velocity` and advances position), agents }`; `crowd.update` on 64 agents allocates nothing after the first call (test with a counting allocator stub or by asserting array identities); `exportNavMesh(mesh) → ArrayBuffer` and `importNavMesh(buffer)` (a game bakes at build time and ships the bytes; the engine never fetches); unit tests (bake of a floor with a wall leaves a hole where the wall is; slope filter; radius erosion shrinks the walkable area; funnel path around a corner is shorter than the portal-midpoint path; off-mesh link is used when it is cheaper; raycast stops at the edge; crowd: two agents head-on sidestep and never overlap; export/import round-trips byte-equal); harness `navmesh.html` on the matrix; documented.
