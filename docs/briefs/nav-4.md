## Goal

The pieces between "a path exists" and "fifty things walk it well": a crowd that stays on the navmesh and follows corridors without a per-agent path copy, dynamic obstacles that carve the mesh and grid at runtime, area types with per-area costs on the mesh, a time-sliced path query so a hundred requests a frame never hitch, mesh flow fields for many-to-one movement, and the two nav-3 wishes. All CPU, allocation-free after warm-up, no new ties outside `nav`.

STATUS row, *done when*:

- **nav-3 wishes**: `FlowField.directionAt(x, y, out)` writes `[dx, dy, stepCost]` (the cost of the step it points along, `Infinity` off-field); `hasLineOfWalkable(grid, a, b, { edgeCost })` honours the hook per cell pair it crosses so `smoothPath` keeps a bend at a cliff (default: the grid's own hook; `null` opts out). Tests: a one-way ledge is not shortcut; the cost matches `findPath`'s.
- **Area types** (`src/nav/mesh/areas.ts`): `NavMesh` polys carry an `area: Uint8Array` (0 default), `markArea(mesh, box | convex polygon, area)` sets polys whose centre is inside, `NavMeshQuery` options gain `areaCost: Float32Array(256)` (multiplier; `Infinity` excludes) and `areaMask`; `bakeNavMesh` accepts `areas: [{ shape, area }]` so the bake stamps them; serialisation carries the array (format version bump, old bytes load with area 0). Tests: a mud area doubles the path cost; an excluded area routes around; round-trips through export/import.
- **Dynamic obstacles** (`src/nav/obstacles.ts`): `createObstacleSet(mesh | grid, { maxObstacles })`, `add({ x, z, radius } | { x, z, w, d, yaw })` → id, `move(id, x, z)`, `remove(id)`, `apply()` re-evaluates only touched tiles/cells (mesh: marks affected polys with a reserved area 255 and splits nothing; grid: writes a cost layer the grid's `edgeCost` reads) and bumps `version`; queries stale-check as today. Tests: a path through a doorway reroutes after an obstacle is added and returns after removal; `apply` with no moves does nothing (version unchanged); affected poly count is bounded by the obstacle's footprint.
- **Path query budget** (`src/nav/query-queue.ts`): `createPathQueue(mesh | grid, { maxQueries, iterationsPerUpdate })`, `request(from, to, out: NavPath | NavPath3, opts)` → ticket, `update()` runs A* in slices across pending tickets (round robin, `iterationsPerUpdate` node pops total), `status(ticket)` `'pending' | 'done' | 'failed'`, `cancel(ticket)`; a finished query writes the path and fires `onDone`. The sliced search shares the heap and open/closed arrays per queue; a stale mesh/grid version restarts the affected queries. Tests: 200 requests on a 200×200 grid finish within N updates with the same paths `findPath` gives; a cancelled ticket writes nothing; the per-update pop count is respected.
- **Crowd on the mesh** (`src/nav/crowd.ts` + new `src/nav/corridor.ts`): `createCorridor(mesh, maxWaypoints)` holds one agent's poly corridor (the `findPath3` poly list) and `corridor.advance(x, z)` drops passed polys and returns the next steering target via string pulling over the remaining polys only (no per-frame full path); `Crowd` gains `attach(mesh)` so `update(dt)` clamps every agent to the mesh (`findNearestPoly` per agent only when it left its poly, else the poly it is on) and reads `y` from `height`; `CrowdAgent` gains `y`, `poly`, `corridor` (optional), `targetReached`; `crowd.setTarget(index, x, y, z)` requests a path (through the queue above when given, else synchronous) and feeds `prefVelocity` from `corridor.advance` + `steer.arrive` each update. Obstacles from the set above are avoided as static ORCA lines (`crowd.obstacles(set)`). Tests: 32 agents cross a mesh with a pillar and all reach within tolerance without leaving the mesh (`findNearestPoly` distance < radius every step); an agent whose corridor is invalidated by a carve replans once.
- **Mesh flow field** (`src/nav/mesh/flow3.ts`): `createFlowField3(mesh, goals: NavPoint3[], opts)` per-poly Dijkstra with area costs (one direction per poly toward the next portal's midpoint, plus a per-poly distance), `direction3(x, y, z, out)`, incremental `update()` on version change. Test: every poly's direction leads to a poly with a smaller distance; matches `findPath3` length within 10% on a corridor mesh.
- **Harness**: `harness/nav4.html` + `nav4.ts` + `nav4-state.ts`: `?crowd` (48 agents on the navmesh with two pillars and a `?carve` obstacle dropped at t=2 s; state `onMesh` (fraction clamped within radius), `reached`, `replans`), `?queue` (200 requests per second on a grid, state `pending`, `doneTotal`, `maxUpdateMs`), `?areas` (a mud patch: path with and without `areaCost`, state `lengthMud`, `lengthPlain`), `?flow3` (agents following a mesh flow field, state `arrived`), `?still` parks. `e2e/nav4.spec.ts` (E-017 polling), existing nav/navmesh specs green, `pnpm snap:check` 0 px.
