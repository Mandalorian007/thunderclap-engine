## Goal

A game built on the engine ships to iOS and Android as a store app with no engine change: a `@thunderclap-engine/host-capacitor` package fills the `Host` interface from Capacitor's plugins the way `@thunderclap-engine/host-electron` fills it from a preload bridge, and the engine gains the three host facets every mobile shell needs and the web host can also answer: lifecycle (pause/resume), haptics, and safe-area insets. All additive; the web host keeps working unchanged.

STATUS row, *done when*:

- **engine (`src/host`)**: `HostKind` gains `'capacitor'`; `Host` gains optional `lifecycle: HostLifecycle { state(): 'active' | 'background', watch(fn): () => void }`, `haptics?: HostHaptics { available(): boolean, impact(style: 'light' | 'medium' | 'heavy'): void, notification(kind: 'success' | 'warning' | 'error'): void, vibrate(ms: number): void }`, `safeArea?: HostSafeArea { insets(): { top, right, bottom, left } (CSS px), watch(fn) }`; `createWebHost` fills all three (lifecycle from `document.visibilitychange` + `pagehide`; haptics from `navigator.vibrate` when present, `available()` false otherwise; safe area from `env(safe-area-inset-*)` read through a probe element, re-read on resize); `GameLoop` (or `createGame`) subscribes to `host.lifecycle` when present: `background` stops requesting frames and pauses audio through the mixer's existing suspend path if one exists (else document the wish), `active` resumes; a `game.on('lifecycle', state)` event (or the existing events bus) so a game autosaves on background; `ui` layout reads `host.safeArea` when present and pads the `top`/`bottom` regions (one function; the harness `?safe=44,0,34,0` query simulates insets so an e2e can probe it). Unit tests with stub windows.
- **package (`packages/host-capacitor`)**: `createCapacitorHost(opts?: { plugins?: Partial<CapacitorPlugins>, base?: Host })` returns a `Host` with `kind: 'capacitor'`: frames from the WebView's `requestAnimationFrame`; `openExternal` through `@capacitor/browser` (falls back to `window.open`); `copyText` through `@capacitor/clipboard`; `fullscreen` reports `available() false` and `toggle` resolves false (a store app is already fullscreen) but honours `lockLandscape` through `@capacitor/screen-orientation`; `storage` through `@capacitor/preferences` wrapped as a synchronous `StorageLike` over an in-memory mirror that writes through (document the semantics: reads are sync from the mirror, writes are async to disk, `open()` resolves after the first hydrate via `await host.ready`); `lifecycle` from `@capacitor/app` `appStateChange` and `pause`/`resume`; `haptics` from `@capacitor/haptics`; `safeArea` from `env()` like the web host; `window` absent. Capacitor packages are **peer** dependencies, injected through `plugins` so tests run in Node with fakes and the package has no hard runtime dependency; `pnpm check:host-capacitor` (typecheck + tests) chained into root `check` after `check:host-electron`; README with the ten-line `capacitor.config.ts` + `npx cap add ios/android` recipe and what the game does for the back button (Android `backButton` is surfaced as `host.lifecycle`? no: as `host.back?: { watch(fn) }` on this host only, documented as optional).
- Harness: `harness/host.html` (or extend an existing platform page if one probes the host) with state `lifecycle`, `safeArea`, `hapticsAvailable`, `regionsTop` (the layout's top region y after insets); `e2e/host.spec.ts`: `?safe=44,0,34,0` pushes the top region down by 44 and the bottom up by 34; simulated `visibilitychange` to hidden stops frame counting within 200 ms and resumes on visible.
- Docs: host README (facets + capacitor), platform or ui README (safe area), CHANGELOG one block, ARCHITECTURE *Host* sentence, root README (packages table row, `check` comment).
