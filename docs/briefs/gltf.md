# Brief: ws/gltf

Read `docs/briefs/common.md` first, then `docs/VISION.md` (pillar 4: "glTF is secondary", style comes from shaders; rule: no network calls from the engine; no runtime dependencies), DECISIONS E-013; `ARCHITECTURE.md` *Transforms*, *Renderer*, *Materials*; `src/render/README.md` (Meshes, vertex layouts, Textures, texture arrays, Materials), `src/render/mesh.ts` (`VERTEX_LAYOUT_3D`, `MeshDesc`, `MeshUpdate`, `MeshBounds` once ws/cull merges; if `MeshBounds` is not on main yet, compute bounds in your parser as `{ center, radius }` and leave wiring to the integrator), `src/render/transform.ts`, `src/render/material.ts`, `src/render/texture.ts` (`loadTextureArray`, `PixelSource`), `harness/mesh.ts` (a lit mesh page to copy).

## Goal

A game loads a glTF 2.0 scene into engine meshes, transforms, textures and a lit material in one call, from bytes it fetched itself. Static geometry only in this step. No dependency, no network call from the engine.

STATUS row, *done when*: `parseGltf(bytes | { json, buffers })` gives an engine-free `GltfDocument` (.glb and .gltf); `loadGltf(renderer, doc, opts?)` gives `Mesh`es in `VERTEX_LAYOUT_3D`, a `Transform` per node, `Texture`s for base colour, and a `GltfScene.draw(frame)`; `@thunderclap/engine/assets` subpath; unit tests parse a generated .glb; harness `gltf.html` renders a generated scene on the matrix; documented.

## Scope

1. **Parser (pure).** `src/assets/gltf.ts`: `parseGltf(source: ArrayBuffer | { json: GltfJson; buffers: ArrayBuffer[] }): GltfDocument`. Handles the GLB container (magic, JSON chunk, BIN chunk), embedded `data:` URIs in buffers and images, and accessors (float, normalised and unnormalised integer component types, strides, sparse not required: throw with a clear message). Output per primitive: position, normal (generated flat if missing), uv0 (zeros if missing), colour0 (ones if missing), indices (generated if missing; `triangles` mode only, other modes throw), material index, and bounds from the accessor min/max. Per node: local 3×4 or 4×4 matrix resolved from TRS, parent chain, mesh index. Per material: base colour factor, base colour texture index, texcoord, double-sidedness, alpha mode. Per image: bytes and mime type, or the uri for the game to resolve. No DOM, no GPU: this file runs in Node tests.
2. **External resources.** `GltfDocument.externalUris: string[]`; `loadGltf` takes `opts.resources?: Record<uri, ArrayBuffer | ImageBitmap>` the game fetched. The engine never fetches. Missing resource: throw naming the uri.
3. **Loader.** `src/assets/gltf-load.ts`: `loadGltf(renderer: Renderer, doc: GltfDocument, opts?: { resources?; material?: Material; label? }): Promise<GltfScene>`. Images decode through `createImageBitmap` on a `Blob`; textures through the existing `Texture` path (one 2D texture each, mips via `createTexture({ mips: true })` + `generateMipmaps` if cheap; else none, say so). One `Mesh` per primitive, interleaved into `VERTEX_LAYOUT_3D` (position, normal, uv, colour; check the exact float order in `mesh.ts`). `GltfScene { meshes; textures; nodes: { transform: Transform; mesh: Mesh; material: Material }[]; bounds: { center; radius }; draw(frame: FrameSink | the frame type `harness/mesh.ts` uses); destroy() }`. Default material: a lit textured material built with `materialPrelude` from the engine's lights block (copy the harness mesh shader; sample base colour × factor × vertex colour); games pass their own. Zero allocations per frame in `draw`.
4. **Tests.** `src/assets/gltf.test.ts`: a tiny GLB writer in the test file builds a two-node scene (textured cube + untextured plane with a TRS node) and asserts every parsed field, bounds, flat normals, the data-uri path, and error messages. `gltf-load.test.ts` on the fake GPU: mesh and texture counts, vertex float order, `draw` pushes one instance per node.
5. **Harness.** `harness/gltf.html` + `gltf.ts` + `gltf-state.ts`: builds the same GLB in the page (import the writer from a `harness/` helper, not from tests), loads it, orbits like `mesh.html`; state exposes node count, mesh count, texture count and a probe pixel at the cube centre. `e2e/gltf.spec.ts` on the matrix: counts match and the cube pixel is not the clear colour. Fonts/colours: whatever `mesh.html` does.
6. **Subpath and docs.** `src/assets/index.ts` exports `parseGltf`, `loadGltf`, `GltfDocument`, `GltfScene`, the option types and the error class. `package.json` `exports` gains `"./assets": "./src/assets/index.ts"`. Root README module table gains one `assets` row and the harness list gains `gltf.html`. `src/assets/README.md`. `ARCHITECTURE.md`: a new *Assets* paragraph after *FX* (Today: glTF static geometry; Planned: skins, animation, KHR extensions), and the `src/` tree. `CHANGELOG.md` one entry. Check `scripts/check-boundaries.mjs` and `check-docs.mjs` accept the new module (append its name if they list modules; name the lines in the report).

Out of scope: skins, morph targets, animation, KHR extensions (ignore `extensionsRequired` with a thrown error, `extensionsUsed` with a warning in the document's `warnings: string[]`), cameras, lights, Draco.
