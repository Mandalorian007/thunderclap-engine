## Goal

The render core catches up with what post-3 and gltf-materials asked for: a camera that jitters for TAA, previous-frame view matrices for post, optional roughness/metalness and velocity targets written by the standard material and read by SSR/motion blur, mesh draws over an index sub-range, materials that compile only the pipelines they use (so a tangent-reading shader works), per-slot uv transforms and `uv1`, and the small naming and documentation debts. The 2D harness stays pixel-identical and the 2D path pays nothing new.

STATUS row, *done when*:

- **Camera jitter and history**: `Camera.setJitter(x, y)` (clip-space offset in pixels of the current target, applied inside `viewProj`/`invViewProj`, zero by default; `clearJitter()`); `Camera.previousViewProj` + `previousView` (copied by the renderer at the start of each frame's view, before the camera is read; `Float32Array` 16 each) and `PostInputs.view: { viewProj, invViewProj, previousViewProj, previousView, jitter: [x, y] }`. The renderer applies the jitter only when a post processor declares `wantsJitter` (`PostProcessor.wantsJitter?: boolean`), so no existing page moves. Tests: jitter shifts a projected point by the pixel amount; previous matrices lag by one frame; 2D camera never jitters.
- **Aux targets**: `SceneTargetDesc.aux?: { roughMetal?: boolean, velocity?: boolean }` adds `rg8unorm` roughness/metalness and `rg16float` velocity attachments to the scene target (and the external-target variant); the standard material writes both when the target has them (pipeline variant keyed by the target's attachment set, built lazily), velocity from `previousViewProj` × the instance's previous transform (`InstanceList` keeps a previous-matrix lane only when `velocity` is on; skinned draws use the palette's previous frame when `SkinPalette` keeps one, else zero) and the camera's own motion otherwise; `PostInputs.roughMetal` / `PostInputs.velocity` (`Texture | null`). Tests: a target without aux writes identical bytes to before (fake-GPU attachment count); a moving instance yields a non-zero velocity sample in a fake-GPU pipeline-descriptor assertion if the fake supports it, else the e2e below.
- **Index sub-range draws**: `InstanceParams.range?: { first: number, count: number }` (indices) so one mesh with several sub-meshes draws a part per call (`Frame.mesh(mesh, material, transform, { range })`), batched per (mesh, material, range); `Mesh.ranges?: Record<string, { first, count }>` is just storage the loader may fill (name them in `src/assets` only as a wish). Test: two ranges on one mesh produce two draw calls with the right `firstIndex`/`indexCount`.
- **Lazy pipelines + tangent frame**: `Material` builds the 2D pipeline on first 2D draw rather than at construction (`material.pipelineFor(layout, depth)` path unchanged otherwise; a material whose shader reads `v.tangent` and is only drawn in `VERTEX_LAYOUT_3D_TANGENT` now compiles); the prelude gains `engine_local_tangent(v)` that returns the file tangent when the layout has one (`VertexLayout.wgslTangent` flag) and a derivative fallback otherwise; the standard material's normal mapping uses it. Test: a tangent-reading WGSL compiles under the fake GPU without a 2D pipeline being created; `pbr.html?tangents` renders without GPU errors (e2e asserts zero errors and `tangentMeshes ≥ 1` now on shader, not layout).
- **Standard material**: per-slot `uvTransform` and `texCoord: 0 | 1` on every map (`uv1` read from `VERTEX_LAYOUT_3D_UV2` if it exists, else add the layout additively), `occlusionStrength` uniform, `Material.name` (label defaults to it), `Material.depthTest: boolean` (default true; a false material draws over the scene on its layer, for world panels). `src/assets/gltf-load.ts` wires `texCoord`, per-slot transforms and `occlusionStrength` (small, additive edit; name the lines).
- **Debts**: `Renderer.white` delegates to `defaultTextures(device).white` (keep the getter); `LoadTextureArrayOptions.mipFilter` → `filter` with the old name accepted and deprecated; render README *Instance format* table documents the flags float bits 1..23 as layers (`INSTANCE_LAYER_SHIFT`, `INSTANCE_LAYER_BITS`).
- **Harness**: `harness/render4.html` + `render4.ts` + `render4-state.ts`: `?jitter` (a quad under a 2-sample jitter sequence, state `shiftPx`), `?aux` (a roughness gradient and a moving cube under a camera; state `roughSample`, `velocitySample` read back through a tiny debug blit), `?ranges` (one mesh, three ranges, three colours; state `drawCalls`), `?depth-test-off` (a panel quad with `depthTest: false` inside a cube; state `panelVisible`). `e2e/render4.spec.ts` (E-017 polling), existing pbr/mesh/post3 specs green, `pnpm snap:check` 0 px.
- **Docs**: render README sections *Camera jitter and history*, *Aux targets*, *Index ranges*, *Lazy pipelines*, *Standard material* additions, *Instance format* fix; `src/post/README.md` one paragraph pointing TAA/SSR/motion blur at the new inputs (do not switch them over: that is ws/post-4; say so); CHANGELOG block; ARCHITECTURE render clause (one sentence); root README harness list + count line.
