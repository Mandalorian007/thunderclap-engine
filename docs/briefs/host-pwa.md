Read `docs/briefs/common.md` first, then `docs/VISION.md` ("every platform": the browser build is the platform most players meet first; installable, offline, fast second load), DECISIONS D-041 (the `Host` seam), E-013; `packages/host-electron/README.md` and `src/` (the package shape this one copies: a noun-free package reaching the engine only through its exports map, its own `check`, harness, e2e, `pnpm check:boundaries` enforcing both directions), the ws/host-mobile row and backlog wishes in `docs/STATUS.md` (host-capacitor lands alongside: read its report when it is on main, do not depend on it), `src/host/README.md`, `src/host/types.ts` (`Host`, `HostKind`, `HostStorage`, `HostFullscreen`, `HostWindow`, `FrameSource`), `src/host/web.ts` (`createWebHost`: what a PWA host wraps), `src/save/README.md` *Storage* (what saves need from the host), `scripts/create-game.mjs` (the scaffold the template plugs into), `templates/puzzle/vite.config.*` and `index.html` (where a game's manifest and service worker registration would go).

## Goal

`packages/host-pwa`: the installable web shell. A game's build becomes an installable app with an offline cache, an update prompt, an install prompt surfaced through the `Host`, and the engine's `Host` gaining nothing it does not have: everything rides on the existing seam plus a documented `host.pwa` extension the package types. The engine itself stays network-free: the service worker and manifest are the package's and the game's, generated at build time by a tiny vite plugin the package exports.

## Rules

- No network calls from the engine; the package makes none either at runtime beyond the worker's own fetch handling of the game's assets. No analytics, no update server: the update signal is a new worker version.
- `pnpm check:boundaries` must stay green: the package imports only through the engine's exports map; the engine never imports it.
- No runtime dependencies; dev dependencies limited to what host-electron already uses (vite, vitest, playwright).
