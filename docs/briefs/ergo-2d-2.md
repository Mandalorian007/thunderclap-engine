## Goal

The 2D helpers every isometric and side-scrolling game rewrote this week become engine code: a pure isometric projection with an inverse that probes elevation, a tile layer that can draw diamonds in painter order with per-tile lift and interleave sprites between tiles, a parallax wrapper over tile layers, and a 2D camera follow with dead zone, look-ahead and world clamp. Pixel-identical for every existing 2D page.

STATUS row, *done when*:

- **Iso maths** (`src/geom/iso.ts`): `createIso({ tileW, tileH, elevH, originX, originY })` → `{ toScreen(tx, ty, elev, out), toTile(sx, sy, elev, out), depth(tx, ty, elev) }` plus `isoInverseProbe(iso, sx, sy, heightAt: (tx, ty) => number, maxElev, out)` that tries elevations from high to low and keeps the first tile whose height matches (the tactics rule) and `isoHiddenBy(iso, tx, ty, heightAt)` for a top hidden by a taller front neighbour. Pure, allocation-free with `out` params, exported from `src/geom/index.ts` (append at end). Tests: round trips, elevation probing on a two-step ramp, the hidden-top case, depth ordering monotone in `tx + ty`.
- **Tile layer painter mode**: `createTileLayer(…, { order: 'grid' | 'painter', elevation?: (tx, ty) => number, diamond?: boolean })`: `'painter'` emits tiles sorted by `tx + ty` (then elevation) each time the map changes, `diamond` lays tiles on the iso lattice through an `Iso` passed in `opts.iso`, `elevation` lifts a tile by `elevH * elev`. `layer.insert(depthKey, sprite)` lets a sprite batch item be drawn between two tiles: implement as `layer.depthOf(tx, ty, elev)` returning a sortable key and a documented recipe with `SpriteBatch` sorted by the same key (if the batch has no sort key, add `sortKey` as one optional per-sprite number, zero cost when unused: read the batch first). `'grid'` is today's path, untouched. Tests: painter order for a 3×3 with one lifted tile; `depthOf` agrees with `Iso.depth`; zero per-frame allocation when the map is static.
- **Parallax** (`src/render/parallax.ts`): `createParallax(renderer, layers: { layer: TileLayer, factorX, factorY, wrapW?, wrapH? }[])` → `{ update(cameraX, cameraY), layers }` that offsets each layer's origin by `camera * (1 - factor)` wrapped at the pattern period so the layer never runs out; a `Drawable` that draws its layers in order. Tests on the offset math and wrap.
- **2D camera follow** (`src/render/camera-2d.ts`): `createFollow2D(camera, { deadZone: { w, h }, lookAhead: { x, y }, lookAheadSmoothing, smoothing, bounds?: { minX, minY, maxX, maxY }, snapOnStart })` → `{ update(dt, targetX, targetY, velX?, velY?), teleport(x, y), x, y }`; drives the ortho camera's position only (it reads `camera` by the existing setter; name it in the README); clamps the view rect to `bounds` after look-ahead; deterministic on `dt`. Tests: target inside the dead zone moves nothing; exit moves exactly to the zone edge; look-ahead eases toward velocity sign; bounds clamp at a corner; `teleport` has no easing.
- **Harness** `harness/tiles.html` gains `?iso` (a 12×12 diamond map with a two-level ramp, a sprite walking the ramp drawn between tiles, pointer hover picking the tile through `isoInverseProbe`) and `?parallax` (three wrapped layers, a follow-2D camera on a moving dot with a visible dead-zone box); state exposes `hoverTile`, `order`, `drawCalls`, `cameraX`, `cameraY`, `layerOffsets`. `e2e/tiles.spec.ts` adds: `?iso` hover at a computed screen point resolves the lifted tile on every row (compute the point from the same constants); the sprite's probe pixel is drawn over the lower tile and under the higher one; `?parallax` camera stays still while the dot is in the dead zone and moves after; layer offsets differ by factor; existing tiles tests green; `pnpm snap:check` 0 px (the snapshot pages do not use the new options).
- **Docs**: render README *Tile layers* (painter mode, diamond, elevation, depth keys), *Parallax*, *2D camera follow* sections; geom README *Iso* section; CHANGELOG block; ARCHITECTURE Render clause (one sentence); root README count line.
