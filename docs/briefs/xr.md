# Brief: ws/xr

Read `docs/briefs/common.md` first, then `docs/VISION.md` (pillar 1 headset, pillar 2 VR controllers and hands; Forgewilds: stereo cameras, headset controllers; rule 3: WebXR is the only XR binding), DECISIONS E-009, E-010, E-012, E-013; `ARCHITECTURE.md` every *Planned* line that names XR (*Surface*, *Camera*, *Renderer*, *Host*, *Input*); `src/host/README.md`, `src/input/README.md` (pointer sources), `src/render/README.md` (Camera, SceneTarget, two views); `src/host/types.ts`, `src/host/web.ts`, `src/render/scene-target.ts`, `src/render/camera.ts`, `src/input/pointer-sources.ts`, `src/core/game.ts` (the loop and `stack.render` call), `harness/views.ts` (the two-view proof).

## Goal

A game enters VR with one call and nothing else changes: frames come from the XR session, each eye is a `render(frame, camera, target)` into the session's layer with its own camera, controllers are pointers in the router, and leaving VR returns to the screen. WebGPU-only through the WebXR/WebGPU binding (`XRGPUBinding`, `XRProjectionLayer`); no WebGL fallback.

STATUS row, *done when*: `createXrHost(session)` as a `FrameSource`; `XrSurface` giving a `SceneTarget` per eye per frame; per-eye `Camera`s from `XRView`; `XrPointerSource` for controllers/hands; `createGame({ xr })` + `ctx.xr.enter()/exit()`; unit tests on a fake XR system; harness `xr.html` boots on the matrix (no headset: the button reports unsupported).

## Scope

1. **Types.** `src/platform/xr-types.d.ts`: ambient declarations for the WebXR Device API and the WebXR/WebGPU binding (`navigator.xr`, `XRSystem`, `XRSession`, `XRFrame`, `XRView`, `XRViewerPose`, `XRReferenceSpace`, `XRInputSource`, `XRHand`, `XRGPUBinding`, `XRProjectionLayer`, `XRGPUSubImage`) sufficient for the engine; `@webxr-input-profiles` is not a dependency. Guard every use so the engine typechecks and runs where `navigator.xr` is undefined.
2. **Host.** `src/host/xr.ts`: `createXrHost(session, base: Host): Host` whose `requestFrame`/`cancelFrame` wrap `session.requestAnimationFrame` (the callback gets `(timeMs, xrFrame)`; stash the frame where the surface can read it this tick) and whose other members delegate to `base`. `kind: 'xr'`.
3. **Surface and cameras.** `src/platform/xr-surface.ts`: `XrSurface` built from `new XRGPUBinding(session, device)` and `binding.createProjectionLayer({ colorFormat, depthStencilFormat })`; per frame, `views(frame): XrEyeView[]` where each has `camera: Camera` (`Camera.setProjection(mat)` and `setViewMatrix(mat)` added to `camera.ts`, `viewIndex` = eye index, depth on) and `target: SceneTarget` wrapping `binding.getViewSubImage(layer, view)` (`colorTexture`, `depthStencilTexture`, `viewport`). `SceneTarget` gains a way to adopt external textures (`SceneTarget.external({ color, depth, viewport })`; `scene-target.ts` is yours, nobody else owns it). The post stack does not run per eye in this step: eyes render directly to the layer (document as a limitation).
4. **Input.** `src/input/xr-source.ts`: `XrPointerSource implements PointerSource`, polling `session.inputSources` against `referenceSpace` into `PointerSample`s with `x`/`y` NaN, ray from `targetRaySpace`, `select = trigger || pinch`, `secondary = squeeze`; hands via `XRHand` joints when present (pinch distance in metres between index tip and thumb tip). `{ xr: 'trigger' | 'squeeze' | 'pinch', hand? }` bindings already exist in the router; wire them.
5. **Game.** `createGame({ xr?: { referenceSpace?: 'local-floor' | 'local' | 'viewer'; onEnter?; onExit? } })` exposes `ctx.xr: { supported(): Promise<boolean>; enter(): Promise<void>; exit(): Promise<void>; active: boolean }`. On `enter`: request `immersive-vr`, build the XR host, swap the loop's frame source (`GameLoop` needs `setFrames(src)` or a restart; prefer the smallest change in `core/loop.ts`), register the XR pointer source, and in the render step call `stack.render(frame, eye.camera, alpha)` + `renderer.render(frame, eye.camera, eye.target)` per eye, skipping `renderer.endFrame`'s present (add `renderer.endFrame({ present: false })` or equivalent). On `exit` or `session.end`: restore everything. Keep every non-XR path byte-identical.
6. **Tests and harness.** A fake `XRSystem`/`XRSession`/`XRGPUBinding` under `src/testing` or beside the tests drives: two eyes → two `render` calls with `viewIndex` 0/1 and the right viewports; input sources → pointer samples; exit restores the web host. `harness/xr.html` + `xr.ts`: an "Enter VR" button; the state object exposes `supported`, and on the matrix (no XR) the e2e asserts the page boots, `supported === false`, and the 2D/3D scene renders.
