# Brief: ws/demo-voxel

Read `docs/briefs/common.md`, then `docs/briefs/demos-common.md`, then `docs/VISION.md` (Forgewilds is the voxel style the engine must carry: chunk meshes from Workers, perspective camera, fog, water, sky, emissive FX; rule 5: the mesher is the game's, the renderer is the engine's), `demos/arena/**` and `demos/showroom/**` (the 3D demo shape, `__demo` state, the spec route), `src/render/README.md` (*Meshes and vertex layouts*, *Standard material*, *Texture arrays* (`loadTextureArray`, `createTextureArray`), *Lights*, *Shadows*, *Fog*, *Culling*, *Instances*, `Mesh.update` for streaming vertex data), `src/fx/README.md` (`Sky`, `Water`, `Flicker`, world particles), `src/input/README.md` (`Look`, pointer lock, `meshTester`/rays for block picking, touch zones), `src/geom/README.md` (`rayHeightfield` is not what you want; you cast against your own chunk data), `src/post/README.md` (bloom for emissive torches), `src/ui/README.md` (HUD: a crosshair reticle, a hotbar with `ui.slots`).

## Goal

`demos/voxel`: a small Forgewilds-class world. Validates the voxel path end to end with the mesher in the demo: a 8×8 column world of 16³ chunks (height 64, so 4 chunks tall: 256 chunks) generated from 2D value noise with caves, greedy-meshed in a Web Worker (one `Worker` built by vite from `demos/voxel/mesher.worker.ts`; the main thread posts chunk data, gets back transferable `Float32Array`/`Uint32Array` vertex and index buffers, uploads them through `Mesh`), one texture-array material with 8 procedural block textures (canvas-painted: grass top, grass side, dirt, stone, sand, wood, leaves, glowstone) sampled by a per-vertex layer index, per-vertex ambient occlusion (the four-neighbour trick) baked by the mesher into a vertex channel the standard material or a small custom WGSL reads, a day cycle driving the sun direction and `Sky`, fog, sun shadows on the near chunks, a water plane at sea level through `Water`, glowstone emissive through bloom with `Flicker`, a first-person controller (`Look` with pointer lock on desktop, Bedrock-style touch zones on phones, pad), block break and place with a ray against the voxel grid (DDA voxel traversal in the demo) that re-meshes the touched chunk and its neighbours within one frame on the desktop row, a hotbar (`ui.slots`) choosing the block to place, a reticle, and chunk culling by the camera's frustum so a 256-chunk world draws well under 256 calls.

STATUS row, *done when*: `pnpm demo voxel` runs; `__demo` exposes `fps`, `chunks` (meshed count), `drawCalls`, `triangles`, `remeshMs` (last re-mesh round trip), `playerPos`, `selectedBlock`, `lookingAt` (block coords or null), `timeOfDay`; `e2e/demos/voxel.spec.ts`: boots to a steady state with all 256 chunks meshed and no console errors, `drawCalls` under 200 from the spawn view (frustum culling works), a synthetic click breaks the looked-at block (`lookingAt` changes to the block behind or null, `remeshMs` under 50 on desktop), a right-click or the place key places the hotbar block, walking forward for 1 s changes `playerPos`, `?still&time=0.25` parks the day cycle for a stable probe; `demos/voxel/README.md` with *What to look at* (five bullets) and *Known limits*; `pnpm check` and `pnpm test:e2e` green at `E2E_PORT_OFFSET=490`; `pnpm snap:check` 0 px.

## Rules

- The mesher, the noise, the voxel grid, the DDA ray and the chunk bookkeeping live in the demo. The engine supplies the renderer, the material, the texture array, the sky, water, fog, shadows, bloom, the camera, the input and the UI. If you have to copy something that looks like engine code (a vertex layout with a layer index and an AO channel, an `uploadMeshFromTransfer`, a frustum-vs-AABB test), write it the long way in the demo and list the exact wish: those wishes become the ws/voxel-render brief.
- Chunk meshes change at runtime: use `Mesh.update` (or recreate if update cannot grow) and say which path you needed and what it cost.
- Only the Worker is new build surface: a `new Worker(new URL('./mesher.worker.ts', import.meta.url), { type: 'module' })` works under vite with no config; if the harness server config needs anything, say so in the report rather than editing shared config.
- No network, no committed binary assets, no dependencies.
