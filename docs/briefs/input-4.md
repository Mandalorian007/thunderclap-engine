## Goal

One pointer path through `Input`: a single dispatcher owns the DOM listeners and the `pointerType` parse, `Gestures`, `Look`, the router and new touch zones are consumers that can claim a pointer, world panels get a hook that runs after each `update()`, and a two-thumb touch-zone primitive ships in the engine. Recordings made before this brief replay byte-identically.

STATUS row, *done when*:

- **Pointer dispatcher** (`src/input/pointer-dispatch.ts`): `createPointerDispatcher(target, { transform })` attaches `pointerdown/move/up/cancel`, `blur`, `visibilitychange` once, parses `pointerType`, applies capture, and fans out `PointerEvent`-shaped records `{ id, device, button, x, y, clientX, clientY, time, inside }` to registered consumers in order (`add(consumer, priority)`), with `claim(id, owner)` / `release(id)`: a claimed pointer is delivered only to its owner (and to the router for hover if `hoverWhileClaimed`, default false, which answers the orbit-drag hover wish). `Input.attach` builds it; `Gestures` and `Look` register as consumers and drop their own `addEventListener` calls (the feed methods `pointerDown/Move/Up` stay as the test and replay path). Standalone `new Gestures()` / `new Look()` without an `Input` still attach themselves (through a private dispatcher of their own). Tests: one listener set per target (count `addEventListener` calls on a fake element), a claim hides the pointer from the other consumer, release restores it, standalone still works, `pointerType` parsed once (spy).
- **`ScreenPointers.claim`**: the router's screen source honours the dispatcher claim: a claimed pointer stops producing hover hits unless `hoverWhileClaimed`; `Look.orbitFromInput` claims through it. Test: during an orbit drag the router emits no `hit` for that pointer; after release it does.
- **Post-update hook**: `input.onUpdated(fn)` (returns the remover) runs after gestures, look, router and triggers have advanced in `update()`, same tick, in registration order; plus router events `moved` (a routed pointer changed position this tick) and `released` (a button went up) with the same payload shape as `hit`. Test: order of `onUpdated` relative to `pressed()` visibility; `moved` fires once per tick per pointer. Name in the report which of the two the world panel should adopt (do not edit it).
- **Touch zones** (`src/input/touch-zones.ts`): `createTouchZones(input, { zones: { move: { rect: (w, h) => Rect, kind: 'stick' | 'buttons' | 'swipe', deadZone, radius }, act: {...} } })` → `{ zones.move.vector [x, y] | .pressed | .swipe, update(), attach/detach, enabled }`; a pointer that goes down inside a zone is claimed by it (so two thumbs never become a pinch), each zone tracks at most one pointer, `stick` reports a clamped vector from the down point (or from the zone centre with `anchor: 'center'`), `buttons` reports `pressed/held` per sub-rect, `swipe` reports a direction once per gesture; zones feed actions through bindings (`{ zone: 'move', axis: 'x' }` / `{ zone: 'act', button: 'jump' }`) so `input.axis('moveX')` works on touch without raw pointers; recordings capture zone input through the existing pointer feed (no new record kind). Tests: two pointers in two zones give two independent readings and no pinch; a pointer that starts outside every zone is not claimed; bindings resolve.
- **Harness** `harness/input.html` gains `?zones` (two thumb zones drawn as circles over the canvas, a jump button, state `zoneMove`, `zoneJump`, `pinchSeen`) and `?claim` (an orbit drag over a hover target: state `hoverHitsDuringDrag`). `e2e/input.spec.ts` adds: two synthetic touches in two zones read independently and `pinchSeen` stays false (touch rows); orbit drag yields zero hover hits during the drag and hits again after; `onUpdated` ordering through the harness state; existing input tests green; `e2e/replay.spec.ts` green with the checked-in recordings unchanged; `pnpm snap:check` 0 px.
