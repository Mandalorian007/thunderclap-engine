# Brief: ws/ui-inventory

Read `docs/briefs/common.md` first, then DECISIONS E-015 (a Diablo-class action game is the target: it lives or dies on its inventory, loot tooltips and a pad-friendly radial menu), E-010, D-044 (one overlay, CSS px, regions); `src/ui/README.md` whole (`Overlay`, layers, `ui.stack`, *Widgets and helpers*, *HUD widgets*, *Theme*, *Layout API*, *Accessibility checklist*), `src/ui/widgets-2.ts` (the shape of a plain-element widget with a handle and `set` that writes DOM only on change; `WIDGETS2_CSS` injection pattern), `src/ui/hud.ts` (`HudHost`, `themePx`, how a widget hides under modals), `src/ui/padnav.ts` and `menu-nav.ts` (how a pad walks focusables), `src/ui/styles.ts` (tokens), `src/input/README.md` *Gestures* (long-press, pan) and *Rays and the pointer router* (pointer events reach the overlay as DOM events; do not add a router hook), `harness/widgets.ts` + `e2e/widgets.spec.ts` (how a widget page is probed).

## Goal

The screens an action-RPG player spends half their time in, as noun-free overlay widgets: a slot grid with drag-and-drop between grids (mouse, touch, pad), stackable cells with a count badge, item cards as tooltips anchored to a cell or a HUD slot, a radial menu for pad and touch, and a context list. The game supplies the data (`{ id, icon, count, size }` and the card's rows) and the rules (`canDrop`); the engine draws, moves focus, animates and announces.

STATUS row, *done when*:

- **Grid** `grid(opts: GridOptions { cols, rows, cellSize (theme px, 56), gap, label, canDrop?(from, to, item) → boolean, onMove?(from, to, item), onActivate?(cell, item), onFocus?(cell) })` returns `Grid { element, set(cell, item: CellItem | null), get(cell), move(from, to), items, focus(cell), focused, clear(), remove() }` where `CellItem = { id: string, icon: string | HTMLElement | HTMLCanvasElement, count?: number, span?: { w, h } (multi-cell items occupy a rectangle; the anchor cell holds it, covered cells are `data-covered`), tone?: WidgetTone, locked?: boolean }`; `role="grid"` with `role="gridcell"` cells and a roving tabindex: arrows move focus (clamped, not wrapping, `Home`/`End` row ends), Enter/Space activate, a held Enter/Space or the pad's `select` picks up and the next Enter drops (`aria-grabbed`), Escape cancels; the count badge is `.tc-cell-count`; a cell announces its item through `aria-label` built from `item.label ?? item.id` and the count.
- **Drag** between any grids and `ui.slots` strips registered in one `DragContext` (`createDragContext(host: HudHost | Overlay) → DragContext { register(target: DropTarget), unregister, dragging, cancel() }`): pointer drag (mouse, pen) and touch after a long-press (160 ms; a pan before that scrolls the panel), a ghost element following the pointer on the `hud` layer with `pointer-events: none`, the hovered cell gets `data-over` and `data-reject` when `canDrop` is false, drop calls `onMove` on both ends (`from.grid !== to.grid` allowed), a rejected drop snaps the ghost back (120 ms, honours `prefers-reduced-motion`); a drag over a `ui.slots` strip assigns the item to that slot through a `DropTarget` adapter `slotsTarget(slots, onAssign)`. Pad: pick up with `select` on the focused cell, move focus across grids with the pad (`DragContext` walks registered targets in reading order with ArrowLeft/Right at an edge), drop with `select`, cancel with `back`. Works with the existing `PadNav` (no change to it; the grid owns its arrows and tells PadNav to leave them alone the way `segmented` does).
- **Card** `card(opts: CardOptions { title, subtitle?, tone?, rows: CardRow[] (`{ label, value, tone?, compare?: 'up' | 'down' | 'same' }`), footer?, width (theme px, 280) })` returns `Card { element, set(opts), show(anchor: HTMLElement | Rect, placement?: 'auto' | 'right' | 'left' | 'above' | 'below'), hide(), visible }`: a tooltip panel on the `hud` layer placed beside the anchor and flipped to stay inside the frame (`placeCard(anchorRect, size, frame, placement) → { x, y, placement }` pure and tested); `role="tooltip"` with `aria-describedby` set on the anchor while visible; grid and slots show it on focus and on hover after 250 ms, hide on blur, leave, Escape and drag start; the compare arrow is CSS, no icon font.
- **Radial** `radial(opts: RadialOptions { items: RadialItem[] (`{ id, icon, label, disabled? }`, 4–8), radius (theme px, 110), deadzone 0.35, onPick(id), onCancel? })` returns `Radial { element, open(at?: { x, y }), close(), aim(x, y) (a stick vector or a pointer offset from the centre; -1..1), highlighted, pick(), visible }`: a ring of sectors on the `hud` layer centred at `at` (default the frame centre), the sector under the aim is `data-active` with its label in the centre, `pick()` fires `onPick` for the active sector; touch: open on long-press of the trigger the game gives it (the game calls `open`), drag selects, lift picks; `role="menu"` with `role="menuitem"` sectors, arrows rotate the highlight for keyboard users, Enter picks, Escape cancels; hidden under modals like the reticle.
- **Context list** `contextList(items: ContextItem[] (`{ id, label, hint?, disabled?, danger? }`), opts: { at: { x, y } | HTMLElement, onPick, onCancel })` returns `ContextList { element, close() }`: a small `role="menu"` positioned like a card (reuses `placeCard`), ArrowUp/Down with wrap, Enter/Space pick, Escape and outside-click cancel, first item focused on open, focus returned to the opener on close; the grid opens it on `secondary` pointer button, Shift+F10, ContextMenu key and the pad's `secondary` on a focused cell (`onContext?(cell, item, open)` hook so the game supplies the list).
- Styles in `INVENTORY_CSS` injected once as `#tc-ui-inventory` (`ensureInventoryStyles(doc)`), design px through `toFrameUnits`, theme tokens only; everything also reachable as `ui.grid`, `ui.card`, `ui.radial`, `ui.contextList`, `ui.drag` on the `Overlay` (append to the `Overlay` type and `createOverlay`).
- Harness `harness/inventory.html` + `inventory.ts` + `inventory-state.ts`: two grids (6×4 backpack, 2×3 equipment with `canDrop` by `tone`), a `ui.slots` strip as a drop target, cards on hover/focus, a radial opened by `?radial` or a long-press on the canvas, a context list on right-click; state exposes `items` per grid, `dragging`, `cardVisible`, `cardPlacement`, `radialActive`, `contextOpen`, `focused`. `e2e/inventory.spec.ts` on the matrix: mouse drag moves an item between grids; rejected drop snaps back and `items` unchanged; touch long-press then drag moves (touch rows); pad: select picks up, Right at the grid edge crosses to the next grid, select drops; focus shows the card and its placement flips near the right edge; radial `aim(1, 0)` highlights the east sector and `pick` fires; context list opens on right-click and Escape returns focus to the cell; `pnpm snap:check` unchanged (no 2D harness files touched).
- Docs: ui README section *Inventory: `ui.grid`, `ui.card`, `ui.radial`, `ui.contextList`* with a twelve-line example, *Accessibility checklist* additions, CHANGELOG one block, ARCHITECTURE UI clause (one sentence), root README harness list item.
