## Goal

Depth-reading drawables stop lying by a frame. The renderer splits the scene pass at the opaque/blended boundary when a drawable asks, copies the depth attachment at that point, and hands the copy to blended drawables in the same frame. The camera block carries the inverse view-projection so no drawable uploads its own. `blendState` gains `'multiply'`. All additive; a frame with no depth-reading drawable encodes exactly the passes it encodes today (the 2D harness stays pixel-identical and the existing fake-GPU label assertions keep passing unchanged).

STATUS row, *done when*:

- **Same-frame depth hook.** `Drawable` gains optional `afterOpaque?(encoder: GPUCommandEncoder, view: ViewInfo): void` and a `readsDepth?: boolean` flag (or the presence of `afterOpaque` is the flag; pick one and document it). When at least one drawable in a view sets it and the camera has `depthTest`, the view's scene pass is encoded as two render passes over the same attachments: opaque draws (`load: clear` or `load` as today) → pass ends → `renderer` copies the depth attachment into a per-target `depthCopy` texture (`depth32float` or `r32float` through a tiny fullscreen copy if `copyTextureToTexture` cannot copy `depth24plus`; say which in the README) → each `afterOpaque` runs with `ViewInfo { camera, target, depthCopy: GPUTexture, depthView: GPUTextureView, viewport }` → blended draws in a second pass with `load` on colour, emissive and depth. Order and batching within each half are unchanged. `SceneTarget.depthCopy` is the sampleable copy (same lifetime rules as `depth`; recreated on resize; external targets allocate their own). `renderer.stats.passes` (or the existing counter if there is one) shows the extra pass so a test can assert it is absent without the hook.
- **Camera block.** The `camera` uniform gains `inv_view_proj: mat4x4f` (from `camera.invViewProj`), and the README's *Custom materials* bullet lists it; `WGSL_GLOBALS` declares it; the block size constant and the `renderer.test.ts` layout assertion are updated together; a unit test checks that `inv_view_proj × view_proj` of a point round-trips with the fake device's recorded bytes. Keep the existing fields at their offsets (append).
- **Blend.** `BlendMode` gains `'multiply'` (`dst × src`, alpha kept: colour `dst-color`/`zero` style, documented with the exact factors); `MaterialDesc.blend` accepts it; a test covers `blendState('multiply')`.
- **Consumers (minimal, in this branch):** `water.ts` and `particles-world.ts` take the copy from `afterOpaque` when the renderer provides it and fall back to their own copy otherwise (one `if`; no behaviour change when the hook is absent, so their existing tests pass; one new test each asserts the own-copy pass disappears when the hook is used). The water harness drops its second view only if the result is pixel-identical on the water probes; otherwise leave the harness and note it. Decals: switch to `camera.inv_view_proj` and drop the own upload (the decals test that asserts the upload changes accordingly) and use `'multiply'` where its README says it wanted it; if ws/decals has not landed when you start, skip the decals item and say so.
- **Tests:** renderer unit tests with the fake GPU: a view with no hook encodes the same labelled passes as before (assert the exact label list equals today's); a view with one hooked drawable encodes opaque pass, depth copy, blended pass in that order and `afterOpaque` is called once per view with the right target; two views, one hooked, only that one splits; `ortho2d` (no depthTest) never splits even when hooked (documented: the hook needs depth). `pnpm snap:check` 0 px.
- **Harness:** extend `harness/water.ts` (or `particles3d`) state with `depthHook: boolean` and `passes` so `e2e/water.spec.ts` can assert the single-view path renders water with a depth read (`?hook=1` vs default); keep both paths probeable until the harness swap is decided.
- **Docs:** render README *Frame model* gains the split-pass bullet and a *Depth hooks* subsection (eight lines, with the `afterOpaque` signature and when it fires), *Custom materials* lists `inv_view_proj`, `blend` bullets list `multiply`; fx README notes for water/soft particles/decals (one sentence each); CHANGELOG one block; ARCHITECTURE render clause (one sentence).
