## Goal

A UI panel that lives in the world: a quad in 3D (or head-locked in front of the camera) whose face is a canvas the engine paints with the same theme as the DOM overlay, holding a small widget set (label, button, toggle, slider, list, progress) a game drives through the same kind of handles it has on the overlay, hit by any pointer ray (mouse, touch through the camera, pad cursor, headset controller through `XrPointerSource`) so a button in the world presses from every device. The panel repaints only dirty regions and uploads once per frame at most. No DOM, no screen required: this is the UI for a headset and for in-world screens, signs and terminals in any 3D game.

STATUS row, *done when*:

- `createWorldPanel(renderer, opts: WorldPanelOptions { width, height (world units), resolution (px per unit, 256 default), theme?: Theme, background?: 'panel' | 'transparent', billboard?: boolean, headLocked?: { distance, offset: [x, y] } }) → WorldPanel { transform (world matrix the game sets, or the panel updates each frame when head-locked from the camera), drawable (a `Drawable` the game pushes into its frame: one quad, blended, with the panel texture), add(widget) / remove(widget), hitTest(ray) → { x, y, widget } | null (panel-local px), pointerDown/Move/Up(x, y, id) (the router feeds these), focus(widget), dirty, repaint(), dispose() }`.
- **Widgets** painted with Canvas2D in the theme's tokens (`--tc-*` values read once from `theme.ts`, not from the DOM): `label({ text, size, align, tone })`, `button({ text, onPress, disabled })`, `toggle({ text, value, onChange })`, `slider({ min, max, value, step, onChange })`, `list({ items, selected, onSelect, visibleRows })` with scroll by drag and wheel, `progress({ value, tone })`; each has `set(opts)` writing only on change and marking its rect dirty; a simple vertical flow layout with `gap` and `padding` from the theme, and an explicit `rect` override per widget. Hover and pressed states; focus ring for pad and keyboard; disabled dimming.
- **Pointer plumbing**: `worldPanelTarget(panel) → RayTarget` (or whatever the router calls a hit-testable thing; read `pointer-router.ts` and reuse its contract) so `PointerRouter` routes mouse, touch, pad and XR rays to the panel; the panel converts the hit to local px and drives the widgets; pad: `focusNext/Prev` and `activate` on the panel so `PadNav` or the game's pad bindings can drive it without a ray; keyboard: the game forwards `KeyboardEvent`s to `panel.key(event)` if it wants.
- **Text** through the canvas `fillText` with the theme font; `measure` cached per string; a `fontLoaded` promise when `document.fonts` exists; works without `document` (OffscreenCanvas in a Worker is out of scope; say so).
- **Rendering**: one `Mesh` quad, one `Material` with a small WGSL that samples the panel texture with premultiplied alpha, depth-tested by default, `depthTest: false` for head-locked; texture uploaded only when `dirty`; `panel.stats { repaints, uploads, bytes }`.
- **Tests (fake GPU + happy-dom or node canvas stub)**: layout places widgets in flow order; `set` with the same value does not mark dirty; a hit on a button's rect fires `onPress` on up, not down; a slider drag changes value by the right amount; list scroll clamps; `hitTest` misses a ray that passes beside the quad and hits with the right local px for a known transform; head-locked transform follows a moving camera; `uploads` stays 0 across frames with nothing dirty; dispose releases the texture (fake GPU `destroy` recorded).
- **Harness** `harness/world-panel.html` + `world-panel.ts` + `world-panel-state.ts`: two panels on walls in a small `geom` room and one head-locked, each with every widget, the mouse and touch rays through the camera, a pad cursor with `?pad`; state exposes `pressed` (counts per button), `toggle`, `slider`, `listSelected`, `uploads`, `hover` (widget id or null), `headLockedDistance`. `e2e/world-panel.spec.ts` on the matrix: clicking the world position of a button increments `pressed` on every row (desktop and touch), dragging the slider changes `slider`, hover sets `hover` and leaves cleanly, `uploads` stops growing within three frames of the last change, the head-locked panel stays at `distance` as the camera moves. `pnpm snap:check` unchanged.
- **Docs**: ui README section *World panels* (when to use them versus the overlay; the widget list; the pointer plumbing; a twelve-line example), input README one paragraph on routing rays to a panel, CHANGELOG one block, ARCHITECTURE UI clause (one sentence) and Input clause (one sentence).
