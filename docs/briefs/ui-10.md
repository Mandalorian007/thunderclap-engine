## Goal

HUD widgets size themselves sensibly per device. Rails measure what widgets want, not what they currently occupy.

STATUS row, *done when*:

- **Intrinsic rail measure.** A content rail sizes from each widget's `max-content` width, clamped as today.
  - A stretch-width widget contributes its intrinsic width rather than zero, or the rail's current width.
  - Pure test: a text widget whose label grows widens its rail on the next layout, and one whose label shrinks narrows it.
- **Sized meters.** `ui.meter({ size })` accepts either a number or a per-form-factor map, `{ phone?, tablet?, desktop?, default }` (use the layout's existing form-factor names). `meter.setSize(size)` changes it live and re-lays out.
  - Test: an orb with `{ phone: 56, default: 96 }` is 56 px on a phone form and 96 px on desktop.
  - Test: `setSize` relays out once.
- **Harness.** Add a `ui5?orb-sized` variant (additive): orbs in content rails using a per-form-factor size. Assert in `e2e/ui5.spec.ts` that it has 0 overflow warnings and that orb width matches the map on every row.
- **Docs.** The ui README sections, the types list, one CHANGELOG line, and one ARCHITECTURE phrase in the ui clause.
