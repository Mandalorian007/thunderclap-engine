# ThunderClap engine: architecture and contracts

`@thunderclap/engine` is the WebGPU engine The Last Rune is built on. It knows nothing about any game. This file is the target the PM reviews promotions and public API changes against (D-041, [refactor plan](../../docs/engine/refactor-plan.md)). Each contract says what exists **today** (0.2.0-dev) and what is **planned**, with the phase that delivers it.

## Package shape

```
packages/engine/
  package.json        # @thunderclap/engine; the "exports" map is the public API
  src/
    index.ts          # the "." entry: createGame and its types
    audio/  core/  fx/  host/  input/  platform/  post/  render/  save/  ui/
  harness/            # noun-free e2e pages: index.html boots the platform layer (window.__harness);
                      # game.html boots through createGame (window.__harnessGame); ui.html is DOM only
  e2e/                # engine e2e specs, fixtures, ports, itch-style iframe wrapper
  playwright.config.ts  # the viewport/device/wrapper matrix every engine spec runs on
  ARCHITECTURE.md     # this file
  CHANGELOG.md
```

**Test ownership (D-041 addendum 2).** The engine verifies platform capability once, for every game: unit tests (`src/**/*.test.ts`, Vitest) and e2e specs (`e2e/`, Playwright) run against the `harness/` page. Every spec runs on the whole matrix in `playwright.config.ts`: desktop 1280×720 and 1920×1080, iPad 1180×820, four phones (667×320, 844×340, 932×380, 915×360, touch at DPR 2), and the harness inside an itch-style cross-origin iframe. Two upright rows, `phone-port` 390×844 and `tablet-port` 820×1180, run the layout spec only. A new platform capability (host, gestures, layout, lifecycle) adds a probe to the harness and a spec here, not in a game. Games test product only.

Games import only the exports map: `@thunderclap/engine` (the `"."` entry: `createGame` and its types) and `@thunderclap/engine/<module>` for `audio`, `core`, `fx`, `host`, `input`, `platform`, `post`, `render`, `save` and `ui`, plus `@thunderclap/engine/testing` (the recording fake `GPUDevice`, for unit tests only). Each subpath is that module's `index.ts`; anything not re-exported there is internal. `pnpm check:boundaries` (`scripts/check-boundaries.mjs`, part of `pnpm check`) fails if a game, test or script imports a path outside the map or reaches into `packages/engine/` by a relative path, or if anything under `src/` imports a game. Inside the package, modules import each other by relative path.

The package ships TypeScript source; the game's Vite build compiles it. There is no separate engine build until Phase 5 (extraction and publishing).

## Ground rules

1. **Promotion rule.** Code enters the engine only if Last Rune uses it, the next game plausibly would, and its API has zero game nouns.
2. **Dependency direction.** `games/*` imports `@thunderclap/engine`; the engine never imports a game. A game's `rules/` imports nothing from the engine or the DOM.
3. **No runtime dependencies** without a DECISIONS entry (D-008). WebGPU is the only renderer.
4. **Seams, not features.** 3D content and XR are out of scope until after Gate 5. The engine grows the three seams they would plug into (`Surface`, `Camera`, the frame loop) and nothing else on speculation.

## Contracts

**Surface.** Owns the canvas, the swapchain, DPR, the backbuffer size and the letterbox or fill-width fit. It exposes `rect` (CSS px), `size` (device px), `clientToLogical` and `onResize`. Later an `XRSurface` provides a target per eye per frame through the same interface. *Today:* `Surface` / `mountSurface` in `platform/surface.ts` exposes `rect`, `backbuffer` (device px; the planned name is `size`), `clientToLogical`, `logicalToClient`, `onResize` and `setFill` (fill-width), over the pure letterbox math in `platform/letterbox.ts`; `initGpu` configures the swapchain. *Planned:* the `size` rename and the target-per-frame shape arrive with Phase 3's `render(camera, target)`; `XRSurface` is after Gate 5.

**Camera.** A view-projection matrix plus `worldToScreen` and `screenToWorld` (the inverse projection; touch aiming uses it). Presets: `ortho2d(designW, designH)`, where 1 unit = 1 design px, and `fitRect(rect, viewport)`, which fits a world rect into a viewport. Depth test and depth write are camera-preset flags; the 2D preset leaves both off. *Today:* `render/renderer.ts` has a 2D `Camera` (`x`, `y`, `zoom`, `rotation` over the logical space) read from `renderer.camera`; draw order is submission order with no depth. *Planned:* Phase 3 (ws/camera) adds the matrix `Camera`, `mat4` in `core/math.ts` and the camera uniform block.

**Frame loop.** `GameLoop` as today (fixed 60 Hz update, variable render), but `render(camera, target, alpha)` takes the camera and the target as inputs instead of reading them from the renderer. The host decides who schedules frames (rAF, Electron, later `XRSession.requestAnimationFrame`). *Today:* `GameLoop` and `FixedStepper` in `core/loop.ts` (fixed step, `maxFps` cap, pause) call `render(alpha, time)` from `requestAnimationFrame`; `Scene<Ctx, Frame>` and `SceneStack` in `core/scene.ts`. *Planned:* the `render(camera, target, alpha)` signature in Phase 3 (ws/render-call); host-owned scheduling with the host layer.

**Host.** `interface Host { kind; openExternal; copyText; fullscreen; storage; window?; embed }`. Implementations: `web` (detects iframe vs top and wraps today's D-036 link service) and `electron` (preload bridge). After Phase 1 the engine never calls `window.open`, `navigator.clipboard` or `localStorage` directly. *Today:* `host/` (`@thunderclap/engine/host`) has the `Host` type, `createWebHost({ win? })` and `defaultHost()` / `setDefaultHost()`. The web host also exposes `clipboardWriteAllowed()`; `fullscreen` is `{ available, active, toggle, watch }` and `storage` is `{ kind, open(): StorageLike | null }`. `save` (`createSaveStore`, `listSlots`), `persistMixer` and the `externalLink` widget take `host` and default to `defaultHost()`. `window.open`, `navigator.clipboard`, `execCommand` and `localStorage` appear only in `host/web.ts` and `host/web-links.ts`; the fullscreen DOM calls stay in `platform/device.ts`, which the web host wraps. Phase 4 (ws/host-electron) adds `createElectronHost()` in `packages/host-electron` (`@thunderclap/host-electron`): the same interface over the preload bridge `window.thunderclap`, `kind: 'electron'`, storage the renderer's `localStorage` (served from the fixed origin `app://bundle`), and `window` with `close`, `minimize`, `toggleMaximize` and `setTitle`. A game installs it with `setDefaultHost` or passes it to its ctx; the engine never imports it.

**Input.** The action map for keyboard, mouse, touch, pen and gamepad, with `blocked()`, `lastDevice`, queued taps, iframe-safe `preventDefault`, injectable pads and public feed methods for tests; `ui/padnav.ts` drives modal panels from the pad and `ui/menu-nav.ts` (`menuNav`) drives non-modal menus. `Gestures` (`input/gestures.ts`) recognises tap, double tap, long-press (450 ms), pan, drag (with its origin) and pinch (scale) from pointer events, with thresholds in CSS px (pan 10) and positions in game space through the same `PointerTransform`. It reports per tick like `Input`: one discrete gesture per kind per tick (extras queue), continuous ones every tick from `start` to `end` or `cancel`. `input.setGestures(g)` links it: the gestures share `blocked()` and the transform, attach with `Input.attach`, advance in `Input.update()`, and can be bound as actions (`{ gesture: 'tap' | 'doubleTap' | 'longPress' | 'pan' | 'drag' | 'pinch' }`), so a game can map tap to `select` and long-press to `info` without reading gestures. While blocked nothing is reported and a running pan, drag or pinch gets one `cancel`. *Planned:* the `magnify` option (loupe and snap for small targets) arrives with ws/port-altar.

**Layout.** `createOverlay` laid out in CSS px, not design px. A `LayoutSpec` names regions (`top`, `left`, `right`, `bottom`, `cardLane`, `captionLane`, `modal`) per form factor (`phone`, `tablet`, `desktop`, each in `landscape` or `portrait`), with safe areas. Games register widgets against regions and the engine places them with CSS grid. The layout reports the free rect to the camera, so the world frames into what the UI leaves. Density tokens `--tc-text-min`, `--tc-tap-min` and `--tc-text-scale` replace the game's `--lr-*` variables. *Today:* `createOverlay` in `ui/overlay.ts` defaults to `legacyScale: true`, a 1920×1080 design canvas shrunk by one CSS `scale()` transform, with layers for hud, captions, panels and toasts; every game scene still uses it. `createOverlay({ legacyScale: false })` is the CSS-px mode (`data-units="css"`, the root is the surface rect in CSS px, `cssPxTheme` sizes). `createLayout(overlay, spec?)` in `ui/layout.ts` runs on a CSS-px overlay only. It classifies the form factor (`phone-landscape`, `phone-portrait`, `tablet`, `desktop`: a phone is a coarse pointer with a short side of at most 600, or any view under 480), resolves each form's px tracks and grid areas inside the safe area (`env(safe-area-inset-*)`, overridable with `--tc-safe-*` or `setSafeArea`), collapses tracks whose regions have no widgets, and draws the same px grid in the DOM. `layout.add(el, { place: { default, <formFactor> } })` moves a widget between regions on an orientation change; `'hidden'` hides it; `{ region: 'free', rect, reason }` is the escape hatch (logged once with `console.info` and listed in `freeUses`). `layout.freeRect` is the `fill` region, the space the world gets; `onChange` reports every re-layout. `layout.dockCaption()` moves the caption card into `captionLane` (`caption.dock(host)`); the legacy `avoid()` path is unchanged. The layout owns `--tc-tap-min` (44 on touch forms), `--tc-text-min`, `--tc-region-pad`, `--tc-safe-*-px` and `--tc-modal-*` on a CSS-px root, and `device-mode` leaves them alone there; buttons, toggles, sliders and panels honour them. `--tc-text-scale` and `scaleFontSizes` are in `ui/text-scale.ts`; `platform/device-mode.ts` and `ui/rotate-card.ts` are interim API for legacy scenes; the phone stylesheet stays in the game (`phone-styles.ts`). *Planned:* the Phase 3 ports move scenes to CSS-px mode, feed `freeRect` to the camera and delete `avoid()` and `legacyScale`.

**UI, Audio, Save, FX, Post.** The APIs are unchanged; the overlay's scaling model is the one change inside UI. *Today:* `ui/` (overlay stack, panels, widgets, toasts, captions, loupe, external-link widget, theme tokens), `audio/` (WebAudio buses, synth, recipes, mixer persistence), `save/` (versioned slots, migrations, quota- and blocked-storage-safe), `fx/` (GPU particles, flicker) and `post/` (bloom, god rays, fog, vignette, grade, quality tiers). Each module has a README with usage. `save` takes its storage from the host (`host.storage`).

**Scene and Ctx.** `Scene<Ctx, Frame>` and `SceneStack` are in `core/`. *Today:* `createGame(opts)` in `core/game.ts` (exported from the root entry `@thunderclap/engine`, not `./core`, because it is the top layer and pulls in every module) builds the engine's ctx and resolves to `EngineCtx`, or to `null` when WebGPU is missing (the unsupported screen is shown). It blocks browser zoom (double-tap, pinch, ctrl+wheel; option `blockBrowserZoom`, default on), boots the letterboxed surface, and builds the renderer, post stack, particles, host, save (`opts.save(host)`), overlay, pad nav, device mode, audio (with `persistMixer` when `mixerKey` is set) and input (blocked under a modal). It wires resize (renderer, overlay rect, phone scale, fill bands), the fixed-step loop (input → pad nav → `hooks.update` → particles → scenes; `hooks.beforeRender` → scenes → `hooks.afterRender`), page lifecycle (hidden, pagehide, freeze: stop the loop, `hooks.hide`, flush the save; shown: resume) and device loss (halt the loop for good, `hooks.deviceLost`, halt audio, flush, reload screen). `EngineCtx<Action, Save, Ctx>` holds `design`, `surface`, `gpu`, `renderer`, `post`, `particles`, `input`, `padNav`, `audio`, `ui`, `host`, `device`, `save`, `stack`, `loop`, `hooks`, `setFill(key)` and `onDeviceLost(fn)`. A game widens that same object with its nouns (`Object.assign(engine, {...})`), so scenes get one ctx; Last Rune's `GameCtx extends EngineCtx` in `games/last-rune/game/ctx.ts`. *Planned:* `camera`, `layout` and `gestures` join `EngineCtx` in Phases 2 and 3.
