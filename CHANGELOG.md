# Changelog: @thunderclap/engine

Versions follow semver from `engine-v1.0.0`. `pnpm release <version> [--tag] [--dry]` (`scripts/release.mjs`) cuts a release from `main`: it runs `pnpm check` and `pnpm test:e2e`, bumps `package.json`, dates the top "Next (unreleased)" section and commits; with `--tag` it also creates the annotated tag `v<version>`. It never pushes. Entries before this repo existed were written while the engine lived in [The Last Rune](https://github.com/Mandalorian007/last-rune) (`packages/engine`); their decision numbers (`D-0xx`) and paths refer to that repo.

## Next (unreleased)

### Repository
- The engine has its own repo, `Mandalorian007/thunderclap-engine`, with the `packages/engine` history from The Last Rune. It adds a standalone pnpm setup, CI (`pnpm check`), a README and a runnable example (`examples/hello`, `pnpm example`). The Last Rune keeps its in-repo copy for now.

- `packages/host-electron` (`@thunderclap/host-electron`) joins this repo, and the repo becomes a pnpm workspace (`pnpm-workspace.yaml`, `packages/*`) with the engine at the root. New root scripts: `desktop:dev`, `desktop:build`, `test:e2e:desktop`, `check:host-electron`; `pnpm check` runs the last one.
- e2e (ws/flake-client): `e2e/client.spec.ts` "the full mode reads storage through the host" polls `updates > 0` instead of reading it once, since in fixed-step mode frames can render before the first update.

### Fixed
- `Gestures` (ws/gesture-longpress): `pointerMove` checks the pan threshold before the long-press timer, and a contact's travel is cumulative from the down point (`Contact.travel`, every move's distance summed), so a slow drag whose steps are each under 10 px, or whose next move arrives after a long frame, is a pan and never a long-press; a pending long-press is dropped when the travel crosses the threshold, a fired one stays. Root cause of the mesh drag flake (E-019); the spec's 12 px steps stay but are no longer needed.
- e2e under load (ws/flake-input, E-017): `mesh.spec` samples the fog with the page opened on `?still` (`harness/mesh.html` parks the circling lamp behind the far block, away from the sampled ground, and stops the side blocks spinning; `HarnessMeshState.still`), the drag and `look.spec` touch-drag assertions poll yaw and pitch with floors that hold when slow frames coalesce pointer events, and `ui.spec` menuNav polls each focus step; no engine change.

### Added
- Depth post passes (ws/post-depth, VISION pillar 4): `PostSettings.ao: AoSettings` (`enabled` false, `radius` 0.5, `intensity` 1, `bias` 0.02, `power` 1.5) is a half-res screen-space ambient occlusion pass over the scene depth (normals from depth derivatives, 12 spiral samples with interleaved-gradient rotation, a 4×4 depth-aware blur) multiplied into the scene colour before bloom; `PostSettings.dof: DofSettings` (`enabled` false, `focusDistance` 10, `focusRange` 6, `maxBlur` 8 px at output res, `nearBlur` true) computes a circle of confusion from linear depth, gathers 24 CoC-weighted taps at half res and blends sharp and blurred by CoC in the composite. Both blend through `blendTo`; `PostQuality.aoSamples` (12) and `dofTaps` (24) cap them. The renderer fills `PostInputs.depth` and `PostInputs.projection` (`PostProjection`) on frames a depth camera rendered, `null` otherwise, and a frame without depth skips both passes with the composite unchanged (goldens delta 0). `harness/depth-post.html` (`?ao=0`, `?dof=0`) and `e2e/depth-post.spec.ts`.
- Localisation (ws/i18n): `@thunderclap/engine/i18n`, a dependency-free string module. `createI18n(desc: I18nDesc)` (`locale`, `fallback`, `tables: Record<locale, Table | () => Promise<Table>>`, `missing: 'key' | 'throw' | fn`, `onMissing`) returns an `I18n` with `locale`, `locales`, `direction`, `ready`, `t(key, args?)`, `has`, `setLocale(locale): Promise<void>`, `subscribe(fn)`, `formatNumber`, `formatDate`, `formatDuration`, `formatList`. Messages are ICU-style, parsed once per dotted key into an AST (`parseMessage`, `formatMessage`, `MessageSyntaxError` naming key and column): `{name}`, `{n, number[, integer | percent]}`, `{d, date | time[, style]}`, `{count, plural, offset:N =N {…} one {…} other {…}}` with `#` through `Intl.PluralRules`, `selectordinal`, `{g, select, …}`, apostrophe quoting. Lookup walks the locale, its language and each fallback; lazy tables load once with a pending promise per locale and the latest `setLocale` wins. `negotiateLocale(available, requested = navigator.languages, fallback?)`, `requestedLocales`, `directionOf`, `languageOf`, `RTL_LANGUAGES`, `compileTable`, `createIntlCache`. `harness/i18n.html` (locale switcher, plural counter, RTL sample) and `e2e/i18n.spec.ts` on the matrix.
- Batch submit (ws/batch-submit, VISION pillar 3: many instances for a few ms of CPU). In `@thunderclap/engine/render`: `frame.meshes(mesh, material, batch: InstanceBatch)` draws `batch.count` instances from the game's typed arrays, `matrices` (3×4 row-major, `MATRIX3X4_FLOATS` each) and optional `params` (`INSTANCE_PARAM_FLOATS` = 16 floats each, the instance format from `uvRect` on; `writeInstanceParams(dst, offset, params, sizeX?, sizeY?)` fills one from `InstanceParams`; null for the defaults), with optional `bounds` (a world sphere culled once for the batch; without it each instance is culled through the mesh sphere over the array, allocating nothing), `layerBits`, `order` and `castShadow`; a batch is one sort key, one draw (merged with same-state neighbours) and one slice of the frame's upload, and the shadow pass draws it. `renderer.createInstanceList(mesh, material, capacity): InstanceList` is a retained list in its own vertex buffer: `set(i, Transform | matrix, params?, offset?)` (i = `count` appends), `remove(i)` (swap-remove, returns the moved index or -1), `clear()`, `touch(i)`, `matrices`, `params`, `count`, `capacity`, `dirty`, `bounds` (automatic from the mesh sphere through every instance, or `setBounds(sphere | null)`), `layerBits`, `order`, `castShadow`, `destroy()`; `frame.list(list)` uploads only the dirty index range (nothing when unchanged) and draws it culled as one unit. `RenderStats.batches` counts batches and lists drawn; `instances` includes theirs. `frame.mesh` is unchanged (bench before/after in `docs/BENCH.md`'s `instances-*` rungs). `harness/bench.html` gains `?mode=mesh|batch|list`, `?cull=0|1` and `?still`, the ladder `batch-10k[-cull]`, `batch-50k[-cull]`, `list-10k`, `list-50k`, and `e2e/bench.spec.ts` asserts the three modes draw the same instance count and the same pixels.
- Texture registry (ws/texture-registry, E-015; the PBR material's plumbing). In `@thunderclap/engine/render`: `loadTexture(device, source: TextureLayerSource, opts?: LoadTextureOptions)` (`{ mips? = true, filter?: MipFilter, format? = 'rgba8unorm-srgb', label? }`) creates one 2D texture, uploads an image or `PixelSource` as level 0 and fills the full `mipLevelCount` chain with `generateMipmaps`, odd sizes included. `defaultTextures(device): DefaultTextures`, cached per device in a `WeakMap`: `white` (1×1 255 sRGB), `black`, `flatNormal` (128,128,255 linear), `metalRough` (255,255,0 linear: glTF G roughness 1, B metallic 0) and `checker` (8×8 magenta/black, mipmapped). `BindingSet`'s `defaultView` is now optional (`GPUTextureView | null | undefined`): unset 2D slots bind the given view or `defaultTextures(device).white`, so a material with every slot unset draws; the renderer still passes its own `white`, so nothing changes on screen. `loadTextureArray` shares the per-layer upload with `loadTexture`.
- Spot lights and per-light layer masks (ws/spot-lights, VISION pillar 4): `SpotLight { position; direction; color; radius; innerAngle; outerAngle; layers? }` with `Lights.spots` (the first `MAX_SPOT_LIGHTS` = 8 uploaded), and `layers?: number` on `DirectionalLight`, `PointLight` and `SpotLight` (default `ALL_LIGHT_LAYERS`), matched against the instance's `InstanceParams.layers`. `EngineLights` grows after fog by `spot_count`, `sun_layers`, `point_layers: array<vec4u, 4>` and `spots: array<EngineSpotLight, 8>` (`LIGHTS_BLOCK_FLOATS` 168 → 316, one uniform buffer per view 1776 bytes; `LAYERS_OFFSET_FLOATS`, `POINT_LAYERS_OFFSET_FLOATS`, `SPOT_LIGHTS_OFFSET_FLOATS`, `SPOT_LIGHT_FLOATS`; every earlier offset unchanged). The instance flags float now carries the low 23 layer bits above the shadow bit (`packInstanceFlags(receiveShadow, layers)`, `INSTANCE_LAYER_SHIFT`, `INSTANCE_LAYER_BITS`), so the default instance's flags read 2, not 0. New WGSL: `engine_light_accum(world_pos, normal, layer_mask)` (sun × shadow + points + spot cones of the lights sharing a bit with the mask), `engine_lambert_layers(normal, world_pos, layer_mask)`, `engine_instance_layers(flags)` and `engine_spot_cone(cos_theta, cos_outer, cos_inner)` (`spotCone` on the CPU); `engine_lambert(normal, world_pos)` keeps its signature and sums every layer. `harness/lights.html` and `e2e/lights.spec.ts` show a sweeping spot and a point light masked to one of two cubes, on the matrix.
- GPU skinning (ws/skinning, E-015): `VERTEX_LAYOUT_SKINNED` (`VERTEX_SKINNED_FLOATS` 14, `VERTEX_SKINNED_STRIDE` 56, `VERTEX_SKINNED_BUFFER_LAYOUT`: the 3D layout plus `uint8x4` joints at `SKIN_JOINTS_BYTE_OFFSET` 48, `@location(11)`, and `unorm8x4` weights at `SKIN_WEIGHTS_BYTE_OFFSET` 52, `@location(12)`; `VertexLayout.skinned`), `setVertexSkin(bytes, vertex, joints, weights)`, and `SkinPalette(device, { joints, instances?, label? })` (`src/render/skin.ts`; `SkinPaletteDesc`, `JOINT_FLOATS` 12, `SKIN_PALETTE_HEADER_FLOATS` 4): a storage buffer of `instances × joints` row-major 3×4 joint matrices (the layout `anim`'s `skinMatrices` writes) with `set(slot, matrices, offset?)`, `setIdentity(slot)`, `offsetOf(slot)`, `isDirty`, one allocation-free `flush()` per frame and `destroy()`. `BindingDesc.buffers: GPUBuffer[]` binds read-only storage buffers at `@group(1) @binding(BUFFER_BINDING_BASE + i)` (`BUFFER_BINDING_BASE` 16; `BindingSet.setBuffer(slot, buffer)`), so `createMaterial({ buffers: [palette.buffer] })` is the palette binding (`SKIN_PALETTE_BINDING` 16). A draw names its palette slot in `params.w`. `materialPrelude` emits `WGSL_SKIN` (`engine_skin_palette`, `engine_skin(v, position, normal)`) for a skinned layout only; the 2D and 3D preludes are byte-identical to before, and the shadow pass's pipeline for a skinned caster skins through the same `vs_main` (its layout binds the material group as group 1, so the shadow follows the pose). New harness `skin.html` (two tubes, 24 rings, 3 joints, hand-written sway) and `e2e/skin.spec.ts`.
- Standard PBR material (ws/pbr, VISION pillar 4): `createStandardMaterial(renderer, desc)` in `@thunderclap/engine/render` builds a glTF-style metallic-roughness material (GGX, Smith, Schlick, Lambert) from `StandardMaterialDesc` (base colour, metallic-roughness, normal, occlusion and emissive maps with factors, `alphaMode` opaque/mask/blend, `alphaCutoff`, `doubleSided`) lit by the frame's `Lights` with shadow and fog, tinted per instance; `WGSL_PBR` exports `engine_pbr` and `engine_perturb_normal` (derivative tangent frame, no tangent attribute) for custom materials; `STANDARD_WGSL`, `STANDARD_TEXTURE_SLOTS`, `STANDARD_UNIFORM_FLOATS`, `packStandardUniforms`. `harness/pbr.html` (5×5 metal/rough sphere grid, normal-mapped tile) and `e2e/pbr.spec.ts`.
- Sky (ws/sky): `Sky` in `@thunderclap/engine/fx`, a `Drawable` procedural sky drawn as one fullscreen triangle at the far plane (depth test on, write off; `frame.drawable(sky)`): gradient `zenith` → `horizon` → `ground`, sun disc (`sunSize`) and glow (`sunGlow`) at `lights.sun` tinted by its colour, horizon haze towards `lights.fog.color`, night darkening and stars (`stars: true | { density, seed }`, `SkyStars`) once the sun sets, `exposure`. Every field is live; the sun and fog come from the lights block and the sky uploads one 64-byte params block (`SKY_PARAMS_FLOATS`) per frame. The sun disc and stars also go to the emissive target. `skyRay(camera, nx, ny, out)` is the shader's view-ray reconstruction (`SKY_WGSL`) in TypeScript. `harness/sky.html` (`?still` parks the sun at noon) and `e2e/sky.spec.ts`.

- Snapshot gate (ws/snap-gate, E-008): `pnpm snap` captures the 2D harness pages (`smoke` = index.html, `game`, `ui`, `layout`, `gestures`) on the `desktop-1280` row at a fixed frame into committed goldens `e2e/golden/<page>.png`; `pnpm snap:check` recaptures, compares channel by channel (fails above 1/255, the E-008 tolerance), prints the max channel delta and the differing pixel counts per page and writes `screens/diff/<page>.png`. `e2e/golden.spec.ts` runs that comparison inside `pnpm test:e2e` (skipped on other rows) under Playwright's fake clock, installed and paused before navigation with `performance.now` quantised to the frame grid, so every capture is at frame 12 regardless of load. `scripts/snap.mjs` holds the comparison on Playwright's bundled PNG codec (no engine dependency) and compares files offline (`node scripts/snap.mjs compare a.png b.png [diff.png]`). - glTF loading (ws/gltf, VISION pillars 2 and 3): `@thunderclap/engine/assets`. `parseGltf(bytes | { json, buffers })` turns a `.glb` or `.gltf` (GLB container, `data:` URIs, strided and normalised accessors, `matrix` or TRS nodes with parent chains, flat normals and generated indices where the file has none) into an engine-free `GltfDocument` (`nodes`, `meshes`, `materials`, `textures`, `images`, `externalUris`, `warnings`, world `bounds`); `loadGltf(renderer, doc, opts?)` builds one `Mesh` per primitive in `VERTEX_LAYOUT_3D`, one `Transform` per node, one sRGB mipmapped `Texture` per image and one lit `Material` per glTF material (`GLTF_LIT_WGSL`; base colour factor as tint, `MASK` cutoff, `BLEND` as alpha), returning a `GltfScene` with `draw(frame)` (allocation-free) and `destroy()`. `LoadGltfOptions`: `resources` for external URIs, `material`, `label`, `mips`, `decodeImage`. Quaternion helpers on flat arrays: `quatIdentity`, `quatNormalize`, `quatDot`, `quatMultiply`, `quatSlerp`, `quatNlerp`, `quatFromAxisAngle`, `quatFromEuler`. Tests include a step/linear/cubic-spline golden table, a slerp constant-speed check, crossfade weights summing to 1 and `skinMatrices` identity at rest.
- Ribbon trails (ws/trails, E-015): `Trail` in `@thunderclap/engine/fx` (`TrailOptions`: `space: '2d' | 'world'`, `maxPoints`, `width` | `widthCurve`, `color` | `colorCurve`, `fade`, `lifetime`, `minDistance`, `facing: 'camera' | 'up' | [x, y, z]`, `blend`, `texture`, `uvMode: 'stretch' | 'tile'`, `softness`) with `push(x, y, z?)`, `update(dt, camera?)`, `draw(frame)`, `clear()`, `count`, `pointAt`. A ring buffer of points becomes two vertices per point in one preallocated array, uploaded with one `Mesh.update` range per frame over a static index buffer (zero allocations after construction); the unlit `TRAIL_WGSL` / `TRAIL_TEXTURED_WGSL` materials fade toward the ribbon's edges. `TrailBatch` draws many ribbons from one mesh. Harness `trails.html` + `e2e/trails.spec.ts`.
- IK and root motion (ws/ik, E-015) in `@thunderclap/engine/anim`: `createIkChain(skeleton, { root, mid, tip })`, `twoBoneIk(pose, skeleton, worldPose, chain, targetWorld, poleWorld, instanceWorld, { weight?, maxIterations? })` (analytic two-bone solve with a pole vector; unreachable targets straighten the chain; weight blends against the input pose; intermediate twist nodes allowed), `lookAt(pose, skeleton, worldPose, joint, targetWorld, instanceWorld, { weight?, forward?, up?, maxAngle? })`, `extractRootMotion(clip, rootNode, { planar? })` → `{ clip, motion }` (in-place clip keeps the first-frame root translation and yaw; motion carries translation and yaw about +Y relative to the first key; channels copied) and `applyRootMotionDelta(motionClip, t0, t1, outDelta)` (`[dx, dy, dz, yaw]` in the heading frame at `t0`, loop wrap when `t1 < t0`). Harness `ik.html` (a procedural arm following an orbiting target, a head looking at it, 2D canvas, no WebGPU) with `e2e/ik.spec.ts` polling `tipError` while the target moves.
- Spatial audio (ws/spatial-audio, E-013): `audio.listener` (`SpatialListener`) with `set(position, forward, up?)` and `fromCamera(camera)` (any `CameraLike`: a column-major `view` and a `position`, so the renderer's `Camera` fits), written to the context's `AudioListener` through its AudioParams or the deprecated setters, kept from before unlock. `PlayOptions.at: [x, y, z]` routes a voice gain → `PannerNode` → bus, with `PlayOptions.spatial: SpatialOptions` (`refDistance`, `maxDistance`, `rolloff: Rolloff` = `'linear' | 'inverse' | 'exponential'`, `rolloffFactor`, `panningModel` default `'equalpower'`, `cone: ConeOptions`, `direction`). `Voice.setPosition(x, y, z)` and `Voice.setDirection(x, y, z)` move a playing (or still-pending) spatial voice in place. Panners are pooled: an ended voice returns its panner, the next spatial voice reuses it (`audio.pooledPanners`). `PlayOptions.pan` stays the 2D stereo shorthand; `at` wins over it. Where `createPanner` is missing, a spatial voice plays dry.
- Look controls (ws/look, VISION pillar 2): `Look` in `@thunderclap/engine/input` reports `look: { dx, dy }` (radians per tick; +dx turns right, +dy looks up) and `move: { x, y }` (-1..1, +y forward, length ≤ 1) from pointer-locked mouse, a two-zone touch layout (a floating move stick in the left half by default, look drags elsewhere), the pad's left and right sticks (`padSensitivity` radians per second × dt) and named move keys. `request(): Promise<boolean>` / `release()` / `locked` / `onLockChange(fn)` manage the pointer lock. Options `LookOptions` (`sensitivity`, `padSensitivity`, `invertY`, `touch: LookTouchOptions`, `padDeadzone`, `pad`, `getGamepads`, `keys: LookKeys`, `blocked`, `now`); types `LookStick`, `LookEvents`, `MoveZone`. `Input.setLook(look | null)`, `getLook()` and `InputOptions.look` link it (shared `blocked()`, attach, advanced in `update()`); `createGame` builds none. `harness/look.html` walks the cube field in first person; `e2e/look.spec.ts` runs it on the matrix.
- Mesh picking (ws/pick, E-015): three transformed hit testers in `@thunderclap/engine/input`, each reading a `RayTransform` (`Pick<Transform, 'world'>`, the 3×4 world matrix) on every call so moving objects pick as drawn, allocation-free after construction: `sphereTester(transform, bounds: RayBounds, target?)` (`render`'s `MeshBounds` in object space; an ellipsoid under non-uniform scale), `obbTester(transform, halfExtents, target?)` and `meshTester(transform, positions: Float32Array, indices: Uint16Array | Uint32Array | null, target?, opts?: MeshTesterOptions)` (`bounds` rejected first, default computed from the positions; `cullBack`; `stride`/`offset` in floats, default `VERTEX_LAYOUT_3D`'s 12 and 0, so a game passes the `Float32Array` it uploaded). ### Render call (ws/render-call, D-044, E-006, E-009)
- `renderer.render(frame, camera, target = renderer.target)` draws the frame's recorded draws for one camera into a `SceneTarget`. ### Changed
- `renderer.camera` is the matrix `Camera`, `Camera.ortho2d(logicalWidth, logicalHeight)` by default, and can be reassigned. Its `x`, `y`, `zoom` and `rotation` work as before; the ortho2d `viewProjection` uses the old arithmetic, so 2D frames are pixel-identical (checked against `main` with and without a panned, zoomed, rotated camera and the post stack). The renderer uploads globals and the camera block in one 512-byte write per frame.
- **WGSL:** `globals.viewProj` is gone; use `camera.view_proj`. `EngineGlobals` keeps `logicalSize`, `targetSize`, `time` and `dt` (now 32 bytes). The engine's `engine_vertex` and the particle shader project with `camera.view_proj`; a material that only writes `fs_main` needs no change. `renderer.globalsLayout` has a second entry (binding 1); drawables built on it need no change.
- The `Camera` type exported from `@thunderclap/engine/render` is now the class (it was a `{ x, y, zoom, rotation }` interface).
- `GameHooks.hide(reason)` gets the lifecycle reason, `HideReason` (`'hidden' | 'pagehide' | 'freeze'`); hooks that take no argument still fit.
- `EngineCtx`'s and `CreateGameOptions`'s save parameter is `S extends FlushableSave | null`; `createGame`'s defaults to `null` (no save) and is inferred only from `opts.save`, not from a return annotation. Callers that pass `save` see no change.
- Analytics `attach(ctx)` wraps `ctx.hooks.hide` and `ctx.hooks.show` instead of watching the page lifecycle itself; `session_end.reason` comes from `hide(reason)`. `detach` restores all three hooks.
- `createOverlay` builds one root over the whole parent in CSS px, with no transform. `hud` and `captions` sit on the frame (the canvas rect); each layer is its own stacking context (`isolation: isolate`), so a z-index in one never lifts it over a later layer; the base UI is sized in design px of the frame (`frame` units, desktop and tablet) or in CSS px (`css` units, phones) per the layout's form. In `frame` units the focus-ring token rounds up to whole px (`round(up, …, 1px)`): outlines snap down to whole pixels, and the old transform drew the scaled ring at its full width, so a ring under 2 px would have thinned. Native range/select controls on the frame's layers are zoomed by `--tc-zoom`; their focus ring is un-zoomed.
- `platform/device-mode.ts` no longer writes the density tokens (`--tc-tap-min`, `--tc-text-min`); the layout owns them. It keeps `data-phone`, `data-touch`, `data-fill` and the crop and bar vars until ws/camera.
- **Breaking for custom vertex shaders:** the per-instance format is 28 floats (112 bytes) instead of 20: a 3×4 world matrix (`m0..m2` at @location 3..5), `uvRect` @6, `tint` @7, `params` @8, `misc` @9 (emissive, flags, size.xy). `INSTANCE_FLOATS`/`INSTANCE_STRIDE`/`INSTANCE_BUFFER_LAYOUT` change with it. Fragment shaders (`fs_main`) and vertex entries that only wrap `engine_vertex(v)` need no change; existing `VSOut` fields keep their locations. The 2D output is unchanged (a pixel probe differs by at most 1/255 on a handful of channels of rotated sprites, from CPU instead of GPU sin/cos).
- Draws render sorted by `order`, then submission order; with the default `order` this is exactly the old submission order and batching. `renderer.stats.instances` counts only the instances drawn (after layer culling).
- `WidgetHandle.remove()` returns the element to where it was before `layout.add()` (its old parent and position); an element added detached is removed, as before.

### Magnify (ws/port-altar)
- `GestureOptions.magnify` (`MagnifyOptions`: `pitch`, `below` 44, `size` 128, `zoom` 2.5, `lift` 56, `when`, `snap`, `over`, `toClient`, `source`, `className`, `parent`) and `Gestures.setMagnify()`. Each tick a touch pointer is down, `gestures.aim` (`Aim`) holds the aim point (lifted while dragging), the snapped `target` (`MagnifyTarget`, with `data` for the game's cell), and whether the loupe shows; the aim the finger lifted at comes once more with `ended` on the drag's `end` tick. With a `source` canvas the gestures draw a `Loupe` (`gestures.loupeElement`); `destroy()` removes it.
- `snapToGrid(grid, x, y, ok?)` and `loupeSpot(finger, aim, size, view)` in `./input`.
- `MagnifyOptions.clear(target)` (ws/dense-board-3): areas the loupe must leave in sight (`keep`, for example the target and its neighbours) and should rather not cover (`avoid`), client px (`Rect`). With it the loupe goes where `loupeClear(finger, aim, size, view, keep, avoid?)` puts it: the free spot nearest the aim, clear of `keep` and the fingertip, never below the finger, on screen.
- `MagnifyOptions.clear` may also return `spare` (ws/polish-9): areas the loupe should leave in sight when it can, for example labels. They rank below `keep` and the fingertip and above `avoid`: the loupe takes the spot covering the fewest `spare` rects, then one covering no `avoid` rect, then the nearest. With `spare` given, `loupeClear(finger, aim, size, view, keep, avoid?, spare?)` also tries a coarse grid over the view, so it finds a clear spot when there is one. Unit-tested in `magnify.test.ts`.
- Engine tests: `src/input/magnify.test.ts`, the loupe element in `gestures.dom.test.ts`, and two `e2e/gestures.spec.ts` cases on every row (snap off a refused cell, loupe only below 44 CSS px, mouse never aims; a drag aims 56 px up and lands there). The game's `scenes/altar/snap` test moved here.
- dense-board-4: `MagnifyOptions.size` may be a function, read each tick (the loupe is rebuilt when it changes), so a game can use a smaller lens where targets are dense; `magnifySize(m)` reads it. `MagnifyOptions.clear(target, aim)` now also gets the game-space aim point, so the loupe can keep clear of the spot under the finger when nothing snapped. `MagnifyOptions.leader` draws a thin line from the loupe's rim to the snapped target: `LoupeView.leader`, `Loupe.leaderEl` (`tc-loupe-leader`, plus `<className>-leader`) and `loupeLeader(at, size, spot)` in `./ui`. Unit-tested in `magnify.test.ts`.
